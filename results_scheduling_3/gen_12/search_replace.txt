<DESCRIPTION>
This change refactors the core placement logic to be more intelligent and adaptive, incorporating two key improvements:

1.  **Best-Fit Slot Selection:** The original `_find_first_available` method used a "first-fit" heuristic, scheduling an operation in the first available time slot on a local machine. This is replaced with a "best-fit" strategy. The new logic iterates through *all* available time slots within the search horizon on local machines, calculates the score for each, and selects the one with the absolute lowest cost. This allows the scheduler to find cheaper time slots that might be slightly later than the first available one, optimizing the trade-off between waiting and compute cost.

2.  **Dynamic Slack-Based Search Horizon:** The search horizon for local machines was previously determined by a static mapping based on job priority. This is replaced with a more accurate, dynamic calculation based on the job's "slack" (the amount of buffer time before the deadline).
    *   Jobs with little or negative slack (high urgency) are given a short search horizon, forcing a quick placement decision and making them more likely to use the cloud if local resources are congested.
    *   Jobs with ample slack are given a long search horizon, allowing the best-fit algorithm to explore a wider range of future options to find the most cost-effective placement.

This combined approach makes the scheduler more context-aware. It prioritizes speed and deadline adherence for urgent jobs while aggressively seeking cost savings for less critical tasks. The `_find_first_available` helper function has been removed as it is now redundant.
