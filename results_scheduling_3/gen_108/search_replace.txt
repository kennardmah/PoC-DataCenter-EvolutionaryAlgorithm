This edit introduces a more robust and resilient scheduling heuristic by making two primary changes:

1.  **Parameter Overhaul and Correction:** The existing heuristic parameters have been completely revised. The `cloud_aggressiveness_threshold` has been logically inverted to correctly prioritize cloud usage for high-priority jobs (e.g., 'emergency', 'critical') and favor cheaper local resources for low-priority ones. All priority-based dictionaries have been updated to include the 'emergency' category, ensuring that urgent jobs in the earthquake scenario are handled with maximum priority. Parameter values have been re-tuned across the board for a more consistent and aggressive response to job urgency.

2.  **Proactive Capacity Preservation Penalty:** A new penalty term, `preservation_penalty`, has been added to the operation scoring function. This heuristic discourages scheduling an operation on a local server if doing so would reduce the server's available capacity below a "safe" threshold (20%). By penalizing placements that exhaust local resources, the scheduler proactively preserves a capacity buffer. This makes the system more resilient to sudden spikes in demand or unexpected failures, which is particularly beneficial in the earthquake scenario. The load-balancing penalty was also changed to be non-linear (`utilization^2`) to more strongly punish high congestion.

Together, these changes create a scheduler that is more aware of resource scarcity and better equipped to handle high-priority and emergency jobs by making smarter tradeoffs between cost, delay, and system resilience.
