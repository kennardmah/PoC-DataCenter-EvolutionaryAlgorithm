Refactor to Urgency-Driven Placement with Advanced Heuristics
</NAME>

<DESCRIPTION>
This refactoring replaces the monolithic `JobScheduler` with a more modular, urgency-driven design. It integrates several advanced heuristics directly inspired by the recommendations and top-performing evolutionary generations:

1.  **Unified, Continuous Job Urgency Profile (Recommendation 3):**
    *   Introduces `JobUrgencyProfile` to calculate a dynamic `urgency_score` for each job. This score is a continuous value derived from the job's priority, deadline slack, and overall local system load.
    *   This continuous score adaptively tunes critical scheduling parameters (`cloud_aggressiveness_factor`, `search_horizon`, `procrastination_penalty_multiplier`) within the `PlacementDecisionMaker`, replacing the previous discrete, priority-based dictionary lookups. This allows for smoother, more context-sensitive adjustments.

2.  **Proactive Multi-Operation Slack Crunch Penalty (Recommendation 2):**
    *   The `_calculate_operation_score` method within `PlacementDecisionMaker` now includes a significant `multi_op_impact_penalty`.
    *   This penalty activates and escalates if placing the current operation critically reduces the available buffer time for subsequent operations of the *same job*, especially if the remaining slack falls below a dynamically calculated `critical_slack_buffer`. This proactively prevents internal job delays and bottlenecks by encouraging earlier (potentially cloud) or less congested local placements.

3.  **Aggressive, Non-Linear Load Balancing with Hotspot Lookahead (Recommendations 1 & 4):**
    *   The load penalty in `_calculate_operation_score` is revamped for local machines. It now applies a quadratic penalty that strongly escalates for utilization above a `hotspot_utilization_threshold` (e.g., 70%).
    *   This penalty is calculated over the operation's duration *and* a `hotspot_lookahead_window` (e.g., 6 hours), proactively detecting and avoiding future capacity hotspots.
    *   The penalty also scales with the job's urgency, meaning higher-priority jobs are more aggressively routed around congested areas.

4.  **Refined Adaptive Search Horizon with Iterative Expansion (Recommendation 5):**
    *   The `search_horizon` for local placements is dynamically set based on the job's `urgency_score` by `JobUrgencyProfile`. Highly urgent jobs get a tighter initial search window.
    *   If no viable local slot is found within this initial window, the `find_best_placement` method in `PlacementDecisionMaker` now implements an *iterative expansion* strategy, gradually extending the search limit until a slot is found or the maximum allowed horizon is reached. This ensures urgent jobs get priority for early slots while allowing flexibility for less critical tasks.

5.  **Improved Decision Flow and Robust Failsafes:**
    *   The `PlacementDecisionMaker` explicitly benchmarks the best cloud option, then searches for the best local option within its adaptive horizon.
    *   A strategic decision is made comparing these options, influenced by the job's `cloud_aggressiveness_factor`.
    *   Robust failsafe mechanisms are in place: if the adaptive local search fails, it performs an unbounded search on the cheapest local machine. If even that fails (or no local machines exist), it falls back to the cloud benchmark. This guarantees placement.
</DESCRIPTION>

    def _calculate_operation_score(self, server_id: str, start_time: int, op: Operation,
                                   remaining_duration_after_op: int) -> float:
        """Calculates a composite score, incorporating load-balancing and local preference."""
        server = self.inst.servers[server_id]

        elif current_slack_for_op < self.inst.time_horizon / 4:

            slack_ratio = 1.0 + (ratio_to_threshold**2) * 2.0

                                * (start_time - self.current_op_start_time) \
                                * urgency_multiplier * slack_ratio

class JobUrgencyProfile:
    """
    Calculates and holds a dynamic urgency profile for a job, which in turn
    derives key scheduling parameters for the PlacementDecisionMaker.
    """
    def __init__(self, job: Job, current_time: int, total_job_duration: int, system_load: float):
        # Base priority weights (higher is more urgent) - Corrected to match CSV values
        priority_map = {"Emergency": 5.0, "Urgent": 3.0, "High": 2.0, "Medium": 1.0, "Low": 0.5}
        base_priority_urgency = priority_map.get(job.priority, 1.0) # Use job.priority directly

        # Slack urgency: penalize more severely as slack decreases
        current_slack = job.deadline - (current_time + total_job_duration)
        slack_urgency_multiplier = 1.0
        if current_slack < 0:
            # Exponentially increasing urgency for negative slack
            slack_urgency_multiplier = 1.0 + math.exp(abs(current_slack) / 6.0) # Steeper for deep delays
        elif current_slack < TIME_HORIZON / 3: # If slack is less than 8 hours
            # Smoothly increasing urgency as slack approaches threshold
            ratio_to_threshold = (TIME_HORIZON / 3 - current_slack) / (TIME_HORIZON / 3)
            slack_urgency_multiplier = 1.0 + (ratio_to_threshold**2) * 2.0

        self.urgency_score = base_priority_urgency * slack_urgency_multiplier
        self.urgency_score = max(0.5, min(15.0, self.urgency_score)) # Clamp urgency score to reasonable range

        # 1. Cloud Aggressiveness: Higher urgency -> lower factor -> favors cloud speed
        #    Also reduce factor if system-wide local load is high, making cloud more attractive
        #    Tuned values: low urgency prefers local more (higher factor), high urgency prefers cloud (lower factor)
        #    Base factor (1.3 for low urgency) - dynamically adjust based on urgency and system load
        self.cloud_aggressiveness_factor = 1.3 - (0.05 * self.urgency_score)
        system_load_influence = (system_load - 0.5) * 0.2 # If load > 0.5, this is positive -> reduces factor -> more cloud aggressive
        self.cloud_aggressiveness_factor -= system_load_influence
        self.cloud_aggressiveness_factor = max(0.9, min(1.5, self.cloud_aggressiveness_factor)) # Clamp for stability

        # 2. Local Search Horizon: Higher urgency -> shorter initial horizon to find a slot quickly
        self.search_horizon = int(72 / (1 + 0.15 * self.urgency_score))
        self.search_horizon = max(job.operations[0].duration + 1, self.search_horizon, 6) # Min horizon of 6 hours or op duration

        # 3. Procrastination Penalty Multiplier: Higher urgency -> greater penalty for waiting
        self.procrastination_penalty_multiplier = 1.0 + self.urgency_score / 2.0


class PlacementDecisionMaker:
    """Finds the best placement for a single operation using an urgency-driven scoring model."""

    def __init__(self, inst, job, op, capacity_usage, earliest_start, remaining_duration, num_remaining_operations: int, urgency_profile: JobUrgencyProfile):
        self.inst = inst
        self.job = job
        self.op = op
        self.capacity_usage = capacity_usage
        self.earliest_start = earliest_start
        self.remaining_duration = remaining_duration
        self.num_remaining_operations = num_remaining_operations
        self.urgency = urgency_profile
        self.base_procrastination_penalty_factor = 0.05
        self.hotspot_penalty_factor = 25.0 # Increased base factor for stronger effect
        self.hotspot_utilization_threshold = 0.7 # Penalize utilization above 70%
        self.hotspot_lookahead_window = 6 # Look 6 hours into the future for hotspot detection

    def _calculate_operation_score(self, server_id, start_time):
        # 1. Compute Cost
        compute_cost = sum(self.inst.server_cost[server_id][t % self.inst.time_horizon]
                           for t in range(start_time, start_time + self.op.duration))

        # 2. Delay Penalty
        projected_completion = start_time + self.op.duration + self.remaining_duration
        delay = max(0, projected_completion - self.job.deadline)
        delay_penalty = delay * self.job.delay_weight

        # 3. Adaptive Procrastination Penalty
        wait_time = start_time - self.earliest_start
        procrastination_penalty = (wait_time * self.base_procrastination_penalty_factor *
                                   self.urgency.procrastination_penalty_multiplier)

        # Incorporate Multi-Operation Slack Crunch Penalty (Recommendation 2)
        if self.num_remaining_operations > 0:
            job_final_completion_if_op_starts_now = start_time + self.op.duration + self.remaining_duration
            job_final_slack = self.job.deadline - job_final_completion_if_op_starts_now

            # Define a critical slack buffer: remaining duration + buffer per op
            # This accounts for the time needed for subsequent operations
            critical_slack_buffer = self.remaining_duration + (self.num_remaining_operations * self.op.duration * 0.5)

            multi_op_impact_penalty = 0.0
            if job_final_slack < critical_slack_buffer:
                # If slack is less than the critical buffer, apply an exponential penalty
                slack_shortfall = max(0, critical_slack_buffer - job_final_slack)

                # Adjust exponent base: higher urgency, shorter future ops imply steeper penalty
                exponent_base = 0.1 + (0.02 * self.urgency.urgency_score)
                if self.remaining_duration > 0 and self.num_remaining_operations > 0:
                     exponent_base += (0.03 * self.num_remaining_operations * self.op.duration) / self.remaining_duration

                multi_op_impact_penalty = (math.exp(slack_shortfall * exponent_base) - 1.0) * self.job.delay_weight * 0.5

            procrastination_penalty += multi_op_impact_penalty


        # 4. Non-Linear Load-Balancing / Hotspot Avoidance Penalty (Recommendation 1 & 4)
        load_penalty = 0.0
        server = self.inst.servers[server_id]
        if not server.is_cloud:
            load_prio_mult = self.urgency.urgency_score # High urgency means more sensitive to load

            # Check for contention over the operation's duration + lookahead window
            for t in range(start_time, start_time + self.op.duration + self.hotspot_lookahead_window):
                used = self.capacity_usage.get(server_id, {}).get(t, 0)
                prospective_used = used + self.op.capacity_required # Capacity AFTER this op is placed
                available = get_available_capacity(self.inst, server_id, t)

                if available > 0:
                    utilization = prospective_used / available
                    if utilization > self.hotspot_utilization_threshold:
                        # Quadratic penalty for exceeding threshold, scales with how much it's exceeded
                        penalty = (utilization - self.hotspot_utilization_threshold) ** 2
                        load_penalty += penalty * self.hotspot_penalty_factor * load_prio_mult

        # Combine all cost components
        total_score = (compute_cost * self.inst.weights['compute_cost'] +
                       delay_penalty * self.inst.weights['delay_penalty'] +
                       procrastination_penalty + load_penalty)

        return total_score

    def _find_first_available_in_range(self, server_id, start_search, end_search):
        """Finds the first time slot with enough capacity on a server within a range."""
        for t in range(start_search, end_search):
            if has_capacity(self.inst, self.capacity_usage, server_id, t, self.op.duration, self.op.capacity_required):
                return t
        return None

    def find_best_placement(self):
        best_local = PlacementCandidate(float('inf'), None, -1)
        cloud_benchmark = PlacementCandidate(float('inf'), None, -1)

        compatible_servers = [s for s in self.inst.servers.values() if s.server_type == self.op.server_type]
        compatible_local_servers = [s for s in compatible_servers if not s.is_cloud]
        compatible_cloud_servers = [s for s in compatible_servers if s.is_cloud]

        # 1. Establish Cloud Benchmark
        if compatible_cloud_servers:
            cheapest_cloud_id = min(compatible_cloud_servers,
                                    key=lambda s: self.inst.server_cost[s.id][self.earliest_start % TIME_HORIZON]).id
            cloud_benchmark_score = self._calculate_operation_score(cheapest_cloud_id, self.earliest_start)
            cloud_benchmark = PlacementCandidate(cloud_benchmark_score, cheapest_cloud_id, self.earliest_start)

        # 2. Find Best Local Placement within an adaptive and iteratively expanding horizon (Recommendation 5)
        current_search_horizon = self.urgency.search_horizon
        max_search_horizon = self.inst.time_horizon * 3 # Cap at 3 days ahead for local search

        while best_local.server_id is None and current_search_horizon <= max_search_horizon:
            search_limit = self.earliest_start + current_search_horizon
            for server in compatible_local_servers:
                start_t = self._find_first_available_in_range(server.id, self.earliest_start, search_limit)
                if start_t is not None:
                    score = self._calculate_operation_score(server.id, start_t)
                    if score < best_local.score:
                        best_local = PlacementCandidate(score, server.id, start_t)

            if best_local.server_id is None: # If no local slot found in current horizon, expand it
                current_search_horizon += self.inst.time_horizon // 2 # Expand by 12 hours

        # 3. Strategic Decision Logic
        has_local = best_local.server_id is not None
        has_cloud = cloud_benchmark.server_id is not None

        if has_local and has_cloud:
            # If local is significantly better than (cloud_score * aggressiveness_factor), pick local
            if best_local.score < (cloud_benchmark.score * self.urgency.cloud_aggressiveness_factor):
                return best_local.server_id, best_local.start_time
            else: # Otherwise, favor cloud (or if local isn't much better)
                return cloud_benchmark.server_id, cloud_benchmark.start_time
        elif has_local:
            return best_local.server_id, best_local.start_time
        elif has_cloud:
            return cloud_benchmark.server_id, cloud_benchmark.start_time

        # 4. Ultimate Failsafe: If no compatible server or path found (should ideally not be reached)
        raise RuntimeError(f"Could not schedule op for job {self.job.id}, no compatible servers found even with failsafes.")
