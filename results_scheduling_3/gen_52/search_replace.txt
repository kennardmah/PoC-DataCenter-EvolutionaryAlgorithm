<DESCRIPTION>
This edit proposes three coordinated improvements to the scheduling heuristics to create a more coherent and logically sound decision-making process:

1.  **Corrected Load-Balancing Logic:** The `priority_load_multiplier` has been inverted. Previously, high-priority jobs were *less* penalized for choosing congested machines, which could create bottlenecks. The new logic makes high-priority jobs *more* sensitive to machine load, encouraging them to pick less-utilized servers to improve overall system throughput and reduce contention. The `urgent` priority level was also added for consistency with other parameter dictionaries.

2.  **Corrected Cloud Aggressiveness:** The `cloud_aggressiveness_threshold` values have been inverted. The prior logic incorrectly made it harder for critical jobs to use the cloud. The new logic correctly reflects that high-priority jobs should be more willing to use expensive but immediately available cloud resources to meet tight deadlines (threshold < 1.0), while low-priority jobs should be incentivized to wait for cheaper local resources (threshold > 1.0).

3.  **Simplified Scoring Function:** The static `local_preference_bonus` has been removed. This bonus was a blunt instrument, and the trade-off between local and cloud resources is more effectively and dynamically managed by the now-corrected `cloud_aggressiveness_threshold` and other cost components. Removing it simplifies the scoring model and eliminates a "magic number".
</DESCRIPTION>
