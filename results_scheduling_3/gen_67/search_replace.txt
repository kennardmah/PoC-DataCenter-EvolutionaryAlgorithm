This edit refines the job urgency profiling and operation scoring mechanisms, addressing the previous "No changes applied" error by ensuring the SEARCH block is an exact match.

Specifically:
1.  **Unified Urgency Profile Refinement (`JobUrgencyProfile`):**
    *   Renamed `criticality_factor` to `criticality_score` for better clarity.
    *   The calculation for `criticality_score` is slightly adjusted to emphasize urgency more.
    *   The `cloud_tolerance_factor` (now `cloud_aggressiveness_factor`) is re-tuned to be more responsive to the `criticality_score`. Urgent jobs are more willing to use cloud.
    *   The `search_horizon` calculation now directly leverages `criticality_score`, shortening the search window for more critical jobs.
    *   The `procrastination_penalty_multiplier` is also adjusted based on `criticality_score`, increasing the penalty for delaying urgent jobs.

2.  **Predictive Capacity Hotspot Penalty (`PlacementStrategy._calculate_operation_score`):**
    *   The `procrastination_penalty_base` has been slightly reduced to lessen its overall impact.
    *   The `capacity_hotspot_penalty_factor` and `capacity_hotspot_lookahead` are further tuned to make the load balancing more aggressive and predictive.
    *   The hotspot penalty calculation is significantly improved:
        *   It considers current *and future* capacity usage.
        *   It introduces a non-linear penalty for utilization exceeding 50% and 75% thresholds, making it exponentially more expensive to schedule into highly congested future slots.
        *   The penalty is scaled by the operation's `capacity_required` and `duration` to reflect its true impact on the bottleneck. This aligns with the recommendation for "predictive hotspot penalties".

These changes aim to improve overall schedule quality by better prioritizing urgent jobs, more intelligently utilizing local capacity to prevent future bottlenecks, and making more informed cloud vs. local decisions.

        self.cloud_tolerance_factor = 1.0
        if self.job.priority.lower() == "emergency":
            self.cloud_tolerance_factor = 0.7 # Cloud is very attractive, effectively making it cheaper
        elif self.job.priority.lower() == "urgent":
            self.cloud_tolerance_factor = 0.8

        # Small positive slack -> high criticality

        elif self.initial_slack < self.inst.time_horizon / 2: # Within 12 hours of deadline
            self.criticality_score *= (1 + (self.inst.time_horizon / 2 - self.initial_slack) / self.inst.time_horizon)

        self.criticality_score = max(0.5, min(10.0, self.criticality_score)) # Clamp to reasonable range

        # Cloud aggressiveness: Higher criticality -> lower factor -> favors cloud speed
        # Ranges from ~0.7 to 1.1 based on criticality_score
        self.cloud_aggressiveness_factor = 1.2 - (0.1 * self.criticality_score) # Tuned: Slightly less aggressive default
        self.cloud_aggressiveness_factor = max(0.7, min(1.2, self.cloud_aggressiveness_factor)) # Clamp to reasonable range

        # Search horizon: how far into the future local machines are searched
        # Higher criticality -> shorter horizon to find a slot quickly

        # Procrastination Penalty Multiplier: Higher criticality -> greater penalty for waiting

    Manages the evaluation and selection of placements for a single operation.

        self.job = job

        self.capacity_hotspot_penalty_factor = 0.2 # TUNED: Increased from 0.15 to 0.2

    def _calculate_operation_score(self, server_id: str, start_time: int, is_cloud: bool) -> float:
        """Calculates a composite score for a potential placement, adjusted by job urgency and predictive load."""
        compute_cost = sum(self.inst.server_cost[server_id][t % self.inst.time_horizon]
                           for t in range(start_time, start_time + self.op.duration)) * self.inst.weights['compute_cost']

        projected_completion = start_time + self.op.duration + self.remaining_duration
        delay = max(0, projected_completion - self.job.deadline)
        delay_cost = delay * self.job.delay_weight * self.inst.weights['delay_penalty']

        # Procrastination penalty: penalize waiting unnecessarily
        procrastination_penalty = (self.procrastination_penalty_base * (start_time - self.earliest_start) *
                                   self.urgency_profile.procrastination_penalty_multiplier)

        deadline_proximity_penalty = 0.0
        remaining_slack_at_completion = self.job.deadline - projected_completion

            deadline_proximity_penalty = -remaining_slack_at_completion * 20 # Heavier penalty for being late
        elif remaining_slack_at_completion < self.op.duration * 2: # Close to deadline, increasing penalty
            deadline_proximity_penalty = (self.op.duration * 2 - remaining_slack_at_completion) * self.deadline_proximity_penalty_factor

        total_score = compute_cost + delay_cost + procrastination_penalty + deadline_proximity_penalty

        # Add predictive capacity hotspot penalty for local machines
        if not is_cloud:
            hotspot_penalty = 0.0
            # Look ahead across the operation duration + a buffer for future congestion
            evaluation_window_end = start_time + self.op.duration + self.capacity_hotspot_lookahead
            for t in range(start_time, evaluation_window_end):

                    projected_utilization = (current_used + self.op.capacity_required) / available_cap

                    # Non-linear penalty: modest for moderate utilization, sharp increase for high utilization
                    if projected_utilization > 0.75:

            hotspot_penalty *= self.capacity_hotspot_penalty_factor * self.op.capacity_required * self.op.duration

        # Adjust cloud cost based on aggressiveness factor
        if is_cloud:
            total_score *= self.urgency_profile.cloud_aggressiveness_factor

        return total_score
