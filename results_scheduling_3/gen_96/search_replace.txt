<DESCRIPTION>
This edit introduces a new "Capacity Preservation Penalty" to the scoring function for local server placements, while also correcting a subtle bug in the existing load penalty calculation. The goal is to improve the scheduler's resilience, particularly for the earthquake scenario, by discouraging placements that exhaust a machine's absolute capacity.

**Rationale:**
The existing `load_penalty` is based on *utilization percentage*, which can be misleading. A machine with capacity 2 and 1 job has 50% utilization, same as a machine with capacity 10 and 5 jobs. However, the first machine is much closer to saturation and cannot accept another job. This makes the system fragile, as future high-priority jobs might be blocked if no machine has a free slot.

The new penalty addresses this by creating a "safety buffer" of absolute capacity.

**Mechanism:**
1.  **Capacity Preservation Penalty:** A `safe_reserve_fraction` (set to 25%) of a server's total capacity is defined as a safety buffer. When evaluating a placement, the algorithm looks ahead and if the server's remaining capacity drops below this buffer, a non-linear (quadratic) penalty is applied. The penalty's magnitude is proportional to the square of the "shortfall", making it highly sensitive to significant capacity depletion.
2.  **Bug Fix:** The previous `load_penalty` calculation incorrectly applied the current operation's load across the entire lookahead window, overestimating contention. The new implementation correctly applies the load only during the operation's actual execution window.
3.  **Unified Implementation:** Both the corrected `load_penalty` and the new `capacity_preservation_penalty` are calculated within a single, more accurate lookahead loop.

This combined change makes the scheduler smarter about leaving resources available for future, potentially urgent, jobs, thereby improving the overall robustness and quality of the schedule.
