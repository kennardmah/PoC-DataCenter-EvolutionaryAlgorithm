<DESCRIPTION>
This edit introduces a "Capacity Preservation Penalty" to the operation scoring function. The goal is to make the scheduler more resilient and forward-looking, especially in capacity-constrained scenarios like the earthquake emergency. This directly addresses the recommendation to penalize placements that create future "hotspots" by preserving a buffer of capacity on local machines.

The core idea is to discourage scheduling an operation on a local machine if doing so would leave the machine with critically low available capacity (e.g., 1 or 0 units). Preserving this buffer increases the probability that future high-priority jobs can be scheduled locally without resorting to the more expensive cloud.

This new penalty complements the existing load-balancing penalty:
-   **Load-Balancing Penalty (Existing):** Discourages using servers that are busy on average over a time window.
-   **Capacity Preservation Penalty (New):** Applies a sharp, targeted penalty for consuming the last few available capacity slots at the specific time of operation, preventing immediate resource exhaustion.

The penalty is calculated as follows:
1.  It applies only to local (non-cloud) servers.
2.  It triggers if scheduling an operation would leave the machine's available capacity below a `CRITICAL_CAPACITY_THRESHOLD` (set to 2).
3.  The penalty magnitude is inversely proportional to the square of the remaining capacity (`1 / remaining_capacity^2`). This creates a strong, non-linear disincentive for using the very last capacity slots.
4.  The penalty is scaled by the job's priority and delay weight, making the scheduler more protective of resources when considering placements for important jobs.
