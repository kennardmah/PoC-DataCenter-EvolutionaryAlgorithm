<DESCRIPTION>
The current scheduling algorithm performs worse than a previous version. This change re-introduces two key heuristic components from the best-performing prior solution into the current `PlacementEvaluator` class to improve its decision-making.

1.  **Inverse-Priority Load Penalty:** A `priority_load_multiplier` is added to the `PlacementEvaluator`. This multiplier reduces the load-balancing penalty for high-priority jobs (like 'emergency' and 'critical') and increases it for low-priority ones. This allows critical jobs to be scheduled more aggressively into contended time slots if it minimizes their delay, without being overly penalized for creating a temporary "hotspot". This is crucial in emergency scenarios where speed for key jobs is more important than perfectly even load distribution.

2.  **Direct Local Preference Bonus:** A fixed, negative bonus (`local_preference_bonus = -10.0`) is now added to the score of any potential placement on a local (non-cloud) server. This provides a direct and constant incentive to use cheaper local resources, complementing the existing multiplicative `cloud_aggressiveness_threshold`. This makes the decision logic more robust by ensuring local options are always fundamentally preferred, all else being equal.

These two changes are inspired by a previously successful model and aim to restore a better balance between cost, delay, and resource utilization, particularly for high-priority jobs.
</DESCRIPTION>
