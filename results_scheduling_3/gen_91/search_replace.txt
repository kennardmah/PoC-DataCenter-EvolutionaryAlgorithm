<name>
urgency_driven_heuristics
</name>

<description>
This edit introduces a more sophisticated, continuous `job_urgency_score` calculated within the `PlacementEvaluator` for each operation. This score dynamically combines the job's base priority, its current deadline slack, the number of remaining operations, and its age.

Instead of relying on fixed, discrete priority mappings for heuristic parameters (like search horizon, procrastination penalty multiplier, and cloud aggressiveness), these parameters are now dynamically derived from the `job_urgency_score`. This allows for smoother transitions and more nuanced decision-making, adapting to the real-time state of the job and its proximity to the deadline.

Specifically:
1.  **`schedule_job_online`** is updated to pass the current operation index (`op_index`) and the `current_system_time` (representing the job's arrival context) to the `PlacementEvaluator`.
2.  The `**PlacementEvaluator.__init__`** method is extended to store these new contextual parameters.
3.  A new method, **`_calculate_job_urgency()`**, is added to `PlacementEvaluator`. This method computes a numerical urgency score based on a weighted combination of priority, projected slack to deadline, remaining operations, and job age.
4.  The discrete priority maps for **`priority_procrastination_multiplier`**, **`cloud_aggressiveness_threshold`**, and the base for `search_horizon` are replaced by functions that derive these values continuously from the `job_urgency_score`. This allows the scheduler to respond more flexibly to job characteristics.
5.  The unused `local_preference_bonus` parameter has been removed for clarity and efficiency.

This change aims to improve overall schedule quality by making heuristic parameters more adaptive and responsive to the evolving state of individual jobs, particularly in dynamic, online scenarios. By using a continuous urgency score, jobs can be prioritized and placed with greater precision, balancing cost and delay more effectively.
</description>

    def _calculate_score(self, server_id, start_time):
        """Calculates a composite score, including procrastination and load-balancing."""
        # 1. Compute Cost
        compute_cost = sum(self.inst.server_cost[server_id][t % self.inst.time_horizon]
                           for t in range(start_time, start_time + self.op.duration))

        # 2. Delay Penalty
        projected_completion = start_time + self.op.duration + self.remaining_duration
        delay = max(0, projected_completion - self.job.deadline)
        delay_penalty = delay * self.job.delay_weight

        # 3. Adaptive Procrastination Penalty
        wait_time = start_time - self.earliest_start
        urgency_multiplier = self.priority_procrastination_multiplier.get(self.job.priority, 1.0)
        current_slack = self.job.deadline - projected_completion
        slack_scaling_factor = 1.0
        if current_slack <= 0:
            slack_scaling_factor = 1.0 + math.exp(abs(current_slack) / (self.inst.time_horizon / 8.0))
        procrastination_penalty = (wait_time * self.job.delay_weight *
                                   self.base_procrastination_penalty_factor *
                                   urgency_multiplier * slack_scaling_factor)

        # 4. Load-Balancing Penalty (for local machines)
        load_penalty = 0.0
        server = self.inst.servers[server_id]
        if not server.is_cloud:
            window_start = max(0, start_time - self.op.duration)
            window_end = start_time + self.op.duration * 2
            total_utilization = 0.0
            num_timesteps = 0
            for t in range(window_start, window_end):
                used = self.capacity_usage.get(server_id, {}).get(t, 0)
                available = get_available_capacity(self.inst, server_id, t)
                if available > 0:
                    total_utilization += used / available
                num_timesteps += 1
            if num_timesteps > 0:
                avg_utilization = total_utilization / num_timesteps
                load_penalty = avg_utilization * self.load_penalty_factor * self.job.delay_weight

    def __init__(self, inst, job, op, capacity_usage, earliest_start, remaining_duration, op_index, current_system_time):
        self.inst = inst
        self.job = job
        self.op = op
        self.capacity_usage = capacity_usage
        self.earliest_start = earliest_start
        self.remaining_duration = remaining_duration
        self.op_index = op_index # New: current operation index for context
        self.current_system_time = current_system_time # New: global system time for job age

            (s_id, s) for s_id, s in self.inst.servers.items()
            if s.server_type == self.op.server_type
        ]

        # Calculate a continuous urgency score for the current job/operation context
        self.job_urgency_score = self._calculate_job_urgency()

        # Heuristic Parameters (Dynamically derived from urgency)
        self.base_procrastination_penalty_factor = 0.05
        self.load_penalty_factor = 5.0

        # Parameter values now dynamically adjusted based on self.job_urgency_score
        # A higher urgency score means:
        # - Higher procrastination penalty multiplier
        # - Lower cloud preference factor (more aggressive use of cloud to meet deadlines)
        # - Shorter search horizon for local machines (don't wait too long)
        # - Higher load penalty multiplier (avoid congested local machines)

    def _calculate_job_urgency(self) -> float:
        """
        Calculates a continuous urgency score for the current job and operation.
        Combines base priority, deadline slack, remaining operations, and job age.
        """
        # Base priority component (numeric conversion)
        priority_map = {'low': 1.0, 'medium': 2.0, 'high': 3.0, 'urgent': 4.0, 'critical': 5.0, 'emergency': 6.0}
        base_priority_val = priority_map.get(self.job.priority, 2.0) # Default to 'medium'

        # Deadline slack component: more urgent if close to or past deadline
        # Projected total completion time for the job, assuming this op starts at earliest_start
        projected_job_completion = self.earliest_start + self.op.duration + self.remaining_duration
        slack_to_deadline = self.job.deadline - projected_job_completion

        slack_component = 0.0
        if slack_to_deadline < 0: # Already delayed or very tight
            slack_component = abs(slack_to_deadline) / (self.inst.time_horizon / 2.0) * 2.0 # Higher impact if very delayed
        elif slack_to_deadline < self.inst.time_horizon / 4.0: # Getting close to deadline
            slack_component = (self.inst.time_horizon / 4.0 - slack_to_deadline) / (self.inst.time_horizon / 4.0) * 1.0

        # Remaining operations component: more urgent if many ops left
        remaining_ops_count = len(self.job.operations) - self.op_index
        total_ops = len(self.job.operations)
        ops_ratio_component = (remaining_ops_count / total_ops) * 0.5 if total_ops > 0 else 0.0

        # Job age component: older jobs get a slight boost
        job_age = self.earliest_start - self.job.arrival_time
        age_component = job_age / (self.inst.time_horizon * 4.0) * 0.2 # Small boost for old jobs

        # Combine components to get a final urgency score
        urgency = base_priority_val + slack_component + ops_ratio_component + age_component
        return urgency

    def _get_procrastination_multiplier(self) -> float:
        # Higher urgency -> higher penalty for waiting
        return 1.0 + max(0, (self.job_urgency_score - 3.0) * 0.5)

    def _get_cloud_pref_factor(self) -> float:
        # Higher urgency -> more aggressive cloud usage (factor < 1 means cloud is preferred if cost is similar)
        # Scale: urgency ~1 -> factor ~1.5 (local preferred), urgency ~6 -> factor ~0.8 (cloud preferred)
        return max(0.8, min(1.5, 1.25 - (self.job_urgency_score - 2.0) * 0.1))

    def _get_load_multiplier(self) -> float:
        # Higher urgency -> higher penalty for placing on heavily loaded servers
        return 1.0 + max(0, (self.job_urgency_score - 2.0) * 0.2)
