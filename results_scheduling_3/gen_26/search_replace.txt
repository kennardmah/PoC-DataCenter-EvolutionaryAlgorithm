<DESCRIPTION>
The current scheduling logic uses a "first-fit" approach for local machines, where it evaluates only the first available time slot on each server. This is suboptimal as it can miss much cheaper slots that are available slightly later within the search window. This change replaces the "first-fit" with a "best-fit" strategy.

**Key Changes:**
1.  **True Best-Fit Local Search:** The local search logic is rewritten to iterate through *all* available time slots for *all* compatible local machines within the dynamically calculated search horizon. It now identifies the single best placement (lowest objective score) instead of just comparing the first available slot on each machine. This leads to better cost optimization.

2.  **Robust Failsafe Mechanism:** The previous implementation could fail if no slot was found within the limited search horizon. This edit introduces a robust, multi-stage failsafe:
    *   If the primary decision logic (comparing biased cloud vs. local) fails to find a slot, it falls back to the best available option (cloud or local) even if it doesn't meet the bias criteria.
    *   If still no slot is found, it performs an *unbounded* search on the cheapest compatible local machine to guarantee a placement.
    *   As a final resort, if no compatible local machines exist, it will use a cloud server if available.
    This prevents the scheduler from crashing on highly constrained scenarios (like the earthquake).

3.  **Refined Cloud Bias:** The `cloud_bias` parameters have been slightly adjusted to better reflect the strategy for each urgency category, introducing a small default preference for local machines to reduce costs when options are otherwise equal.

These changes make the scheduler more intelligent in its use of local resources and more resilient to capacity contention and failures.
