<DESCRIPTION>
This edit introduces a comprehensive overhaul of the scheduling heuristic, focusing on correctness, more intelligent parameter tuning, and proactive load management.

1.  **Correctness Fix & Parameter Tuning**: The parameter dictionaries for priority-based scheduling (`priority_base_horizon`, etc.) contained incorrect keys (e.g., 'critical', 'high') that did not match the actual job data ('Emergency', 'High', etc.). This has been corrected to use title-cased keys like `Emergency`, `Urgent`, `High`, `Medium`, and `Low`, making the priority-based logic effective for the first time.
2.  **Re-calibrated Heuristics**: The `cloud_aggressiveness_threshold` has been re-tuned to logically favor local resources for low-priority jobs (allowing them to wait for cost savings) while pushing high-priority jobs towards the cloud if local slots aren't immediately available. The `priority_load_multiplier` has been inverted, making high-priority jobs *more* sensitive to machine load, thus steering them away from potential contention and delays.
3.  **Quadratic Hotspot Avoidance**: The previous linear load penalty has been replaced with a more sophisticated non-linear (quadratic) penalty. This new system strongly penalizes scheduling on any local machine where placing the operation would push utilization above a 70% threshold. This proactively prevents the creation of performance hotspots, which is critical for maintaining throughput, especially during the capacity-constrained earthquake scenario.
4.  **Streamlined Logic**: The flat `local_preference_bonus` has been removed, as its role is now more effectively and dynamically handled by the properly tuned `cloud_aggressiveness_threshold`.
