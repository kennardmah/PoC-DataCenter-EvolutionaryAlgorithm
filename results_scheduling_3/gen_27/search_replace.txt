<dynamic_horizon_best_fit_cloud_bias>
This edit refines the online scheduling logic by implementing:
1.  **Dynamic Search Horizon:** The look-ahead window for local machine scheduling (`effective_local_search_horizon`) is now dynamically calculated based on the job's priority and its current slack (time until deadline, considering remaining operation durations). Urgent jobs get a shorter, more focused horizon, while flexible jobs get a longer one to find cost-optimal slots.
2.  **True Best-Fit Local Search:** For local machines, instead of taking the *first* available slot, the scheduler now iterates through *all* feasible slots within the dynamic horizon and selects the one with the absolute lowest overall score. This leads to better resource utilization and cost.
3.  **Adaptive Cloud-Local Tradeoff:** An explicit `CLOUD_AVERSION_FACTOR` is introduced, allowing local placements to be preferred even if they are slightly more expensive than cloud, up to a certain threshold. Furthermore, `PRIORITY_CLOUD_BIAS` modifies the effective cost of cloud for different job priorities, making cloud more attractive for urgent jobs (e.g., emergency) if local resources are constrained or expensive.
4.  **Procrastination Penalty:** A `PROCR_PENALTY_FACTOR` is added to the objective function, penalizing operations that start significantly later than their `current_op_earliest_start`. This encourages earlier scheduling without sacrificing global optimality, especially for non-urgent jobs.
5.  **Robust Failsafe:** The failsafe logic ensures that if no viable option is found within the adaptive horizon for either local or cloud, it will conduct an unbounded search for *any* available slot on the cheapest local machine. If even that fails (e.g., no local machines of that type), it will fall back to using the cloud if compatible cloud servers exist, guaranteeing a placement.

These enhancements aim to balance urgency, cost-efficiency, and resilience by making smarter, more adaptive decisions based on job characteristics and system state.

    BASE_LOCAL_SEARCH_HORIZON = 24  # Base hours to look ahead for local machines
    PROCR_PENALTY_FACTOR = 0.05     # Penalty for delaying start time (per hour)
    CLOUD_AVERSION_FACTOR = 1.2     # Local is preferred if its cost is <= Cloud cost * this factor
                                    # (e.g., if local_cost <= cloud_cost * 1.2, choose local)

    # Priority-based adjustments (e.g., tighter deadlines for urgent jobs)
    PRIORITY_HORIZON_MULTIPLIER = {
        'urgent': 0.5, 'high': 0.8, 'medium': 1.0, 'low': 1.5, 'emergency': 0.3
    }
    PRIORITY_CLOUD_BIAS = { # How much less acceptable is cloud for this priority (factor < 1 means cloud is effectively cheaper)
        'urgent': 0.9, 'high': 0.95, 'medium': 1.0, 'low': 1.05, 'emergency': 0.8
    }

    def _calculate_full_score(server_id, start_time, op, job, remaining_duration):
        """Calculates a composite score including compute, delay, and procrastination."""
        base_objective_cost = operation_objective(inst, server_id, start_time, op, job, remaining_duration)

        # Add a penalty for how long we wait to start the operation
        # This penalizes scheduling far into the future unnecessarily.
        procrastination_cost = PROCR_PENALTY_FACTOR * (start_time - current_op_earliest_start)

        return base_objective_cost + procrastination_cost

    for idx, op in enumerate(job.operations):
        remaining_duration_after_op = sum(o.duration for o in job.operations[idx + 1:])

        # Determine dynamic search horizon for local machines
        total_remaining_job_duration = op.duration + remaining_duration_after_op
        current_job_slack = job.deadline - (current_op_earliest_start + total_remaining_job_duration)

        # Adjust base horizon by priority and slack
        horizon_multiplier = PRIORITY_HORIZON_MULTIPLIER.get(job.priority, 1.0)
        # Reduce horizon if slack is negative or very small, allow more search if large slack
        slack_adjustment_factor = 1.0 + min(1.0, max(-0.5, current_job_slack / (TIME_HORIZON * 2))) # Limit adjustment range

                    best_cloud_server = server_id

            best_overall_placement = (best_cloud_server, current_op_earliest_start)

        best_local_score = float('inf')

        for server_id, server in inst.servers.items():

                    if score < best_local_score:

                        best_local_server = server_id
                        best_local_start = start_time_candidate

        # Step 3: Make the Decision based on comparisons with cloud aversion factor
        chosen_server, chosen_start = None, -1

        if best_local_server is not None and best_local_score <= best_cloud_score * CLOUD_AVERSION_FACTOR:

            chosen_server, chosen_start = best_local_server, best_local_start

            chosen_server, chosen_start = best_cloud_server, current_op_earliest_start
