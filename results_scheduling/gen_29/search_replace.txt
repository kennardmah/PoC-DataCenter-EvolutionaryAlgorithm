<DESCRIPTION>
This mutation introduces a new helper function `_calculate_operation_cost` to accurately determine the cost of running an operation on a given server for a specific duration. This function is then utilized in the scheduling logic.

The core improvement is in the handling of cloud server fallback. When no local server can accommodate an operation, the scheduler now iterates through *all* compatible cloud servers, calculating the cost for each. It then selects the cloud server that offers the minimum compute cost for the operation. This directly addresses the "Cost-Optimized Cloud Server Selection during Immediate Failover" recommendation, aiming to reduce `compute_cost` by always choosing the most economical cloud option when local resources are unavailable or insufficient. This replaces the previous greedy approach of simply picking the first compatible cloud server.
