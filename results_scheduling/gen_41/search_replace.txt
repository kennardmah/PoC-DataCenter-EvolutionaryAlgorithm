<NAME>
integrate_cost_and_tiebreaking_with_failure_penalty
</NAME>

<DESCRIPTION>
This refactoring integrates all cost calculation logic, including compute cost, delay penalties, and a proactive failure penalty, directly into the main operation scheduling loop. This removes the now-redundant `_get_op_schedule_cost` helper function, making the code more cohesive and easier to maintain.

Crucially, it introduces a `failure_penalty` mechanism for local machines, penalizing operations scheduled during foreseen machine failure windows. This penalty is proportional to the expected capacity reduction, operation's capacity requirement relative to the machine's base capacity, and the overlap duration with the failure, scaled by the `delay_penalty` weight. This makes the scheduler proactively avoid risky local resources, improving resilience in the earthquake scenario. Cloud machines are considered failure-proof in this context.

Additionally, the server selection logic is enhanced with a secondary tie-breaking criterion: if multiple scheduling options (local or cloud) yield the exact same minimal total objective score (which combines compute, delay, and failure penalties), the option with the lowest raw compute cost for the current operation is preferred. This ensures that among equally optimal choices in terms of overall score, the most cost-efficient server is selected, further optimizing resource utilization.
</DESCRIPTION>
