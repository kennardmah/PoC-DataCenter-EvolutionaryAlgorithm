<DESCRIPTION>
This refinement improves the cloud server selection logic. Previously, when considering cloud resources, the system simply picked the first compatible cloud server of a given type (`cloud_servers[0]`) without evaluating if other cloud servers of the same type might offer a lower cost. Given that `inst.server_cost` can vary hourly, even for cloud servers, there might be a more cost-effective cloud option available, especially at `current_op_start_time`.

The updated code now iterates through all available cloud servers of the required type. For each cloud server, it calculates the estimated total objective cost using the `_get_op_schedule_cost` function (which accounts for both compute cost and potential future delay penalties). It then selects the cloud server that yields the minimum total objective cost. This ensures that when resorting to cloud resources, the most economical cloud option is chosen, contributing to a lower overall `Total Cost`.
</DESCRIPTION>
