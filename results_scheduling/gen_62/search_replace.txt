<add_resilience_tiebreaking>
Adds a resilience tie-breaking mechanism to local server selection. When multiple local servers can start an operation at the same earliest time and incur the same cost, the scheduler will now prefer the server with higher *current available capacity*. This prioritizes healthier machines, especially beneficial in earthquake scenarios where machine failures are present, making the schedule more robust. The `max_local_resilience` variable tracks the highest available capacity encountered for tied options.
</add_resilience_tiebreaking>
