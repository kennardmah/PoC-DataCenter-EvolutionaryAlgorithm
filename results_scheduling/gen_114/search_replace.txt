<DESCRIPTION>
This set of changes enhances the server selection process by incorporating a more proactive "health score" for local machines into the sorting mechanism.

The key improvements are:
1.  **New Helper Function `_get_projected_min_available_capacity_over_duration`**: This function is introduced within the `Scheduler` class. It calculates the minimum *base* capacity available on a given server over a specified future time window (`start_time` to `start_time + duration`), strictly considering only machine failures and recoveries, not existing capacity usage. This allows the scheduler to assess a server's inherent resilience to upcoming failures.
2.  **Enhanced Server Sorting in `_get_servers_by_type_sorted`**: The `_get_servers_by_type_sorted` method's signature is updated to accept `op_duration`. The sorting key for local servers is then modified to use the output of `_get_projected_min_available_capacity_over_duration`. This means local servers are now prioritized not just by their instantaneous available capacity and current cost, but also by their projected minimum available capacity throughout the *entire duration* of the operation being considered. Servers that are more resilient to future failures (i.e., maintain higher minimum capacity) will be ranked higher.
3.  **Updated Call Site**: The call to `_get_servers_by_type_sorted` in `run_scheduling` is updated to pass the `op.duration`, enabling the more sophisticated sorting logic.

This change aims to improve the robustness of schedules, especially in earthquake scenarios, by proactively guiding operations towards local machines that are predicted to be less affected by capacity degradation during their execution, thereby reducing the likelihood of costly cloud relocations.

        def _get_projected_min_available_capacity_over_duration(self, server_id: str, start_time: int, duration: int) -> int:
            """
            Predicts the minimum *base* capacity available for a server over a future time window,
            considering only machine failures and not current usage. This helps identify resilient machines.
            """
            if self.inst.servers[server_id].is_cloud:
                return float('inf') # Cloud has infinite capacity

            min_proj_capacity = self.inst.servers[server_id].capacity # Start with full capacity
            for t in range(start_time, start_time + duration):
                # We want base capacity minus reduction due to failure, NOT considering current usage.
                # self._get_available_capacity already does this.
                proj_available_at_t = self._get_available_capacity(server_id, t)
                min_proj_capacity = min(min_proj_capacity, proj_available_at_t)
            return int(min_proj_capacity)
