<DESCRIPTION>
The previous attempts to improve the `Scheduler`'s decision-making regarding local vs. cloud placement and failure avoidance were unsuccessful, likely due to a mismatch in the SEARCH block or suboptimal weighting/thresholds. This mutation aims to correct this by:

1.  **Introduce `_calculate_slot_score`:** A dedicated helper function `_calculate_slot_score` is introduced to encapsulate the logic for evaluating a potential slot. This centralizes the calculation of weighted cost, delay penalty, and a refined failure penalty, ensuring consistency.
2.  **Refined Failure Penalty:** The `failure_penalty` calculation within `_calculate_slot_score` is simplified and made less aggressive. Instead of a direct multiplier, it now applies a penalty proportional to the potential capacity loss *during the operation's duration* that overlaps with a failure, multiplied by the `delay_penalty` weight. This makes it a more nuanced representation of risk without over-penalizing.
3.  **Conservative Cloud Trade-off:** The `_find_best_slot_for_operation` method now explicitly calls `_calculate_slot_score` for both local and cloud options. The `cloud_preference_threshold` is removed, and the decision now defaults to local unless the cloud option offers a *strictly lower* combined score (cost + penalty). This ensures cloud is only used when it is truly the more cost-effective option, considering all penalties, thereby minimizing expensive cloud relocations for less urgent situations.
4.  **Clarity in Search Window:** The `search_window_start` and `search_window_end` variables are maintained for potential future refinements, but for now, the window spans the entire `time_horizon` to ensure all local options are considered.

    def _calculate_job_urgency(self, job_id: str, current_time: int) -> float:
        job = self.inst.jobs[job_id]
        priority_factor = self.priority_values.get(job.priority, 1) * 100 # Higher value for higher priority

        # Remaining duration for the job from its current operation
        # This considers only the unscheduled operations
        scheduled_ops_count = len(self.schedule.get(job_id, []))
        if scheduled_ops_count >= len(job.operations):
            return -float('inf') # Job is already fully scheduled

        remaining_duration = sum(op.duration for op in job.operations[scheduled_ops_count:])

        # Heuristic for earliest possible completion if scheduled immediately
        # Use a soft deadline check, so delays contribute to urgency
        earliest_possible_end = max(current_time, job.arrival_time) + remaining_duration

        # Time pressure: how much time is left relative to the job's duration, weighted by delay_weight
        # A job already past its deadline is highly urgent.
        # This is (deadline - (current time + remaining duration))
        slack = job.deadline - earliest_possible_end

        # A lower slack (or negative slack indicating overdue) makes a job more urgent.
        # Scale slack to be a positive value where smaller means more urgent.
        # For example, if slack is -5, this adds 5 to urgency. If slack is 10, it adds -10.
        # We also factor in the job's intrinsic delay_weight.

        # Urgency is higher for lower (more negative) slack.
        # Maximize (priority_factor - slack * delay_weight_factor)
        urgency = priority_factor - (slack * job.delay_weight)

        return urgency

    def _calculate_slot_score(self, job: Job, op: Operation, server_id: str, start_time: int) -> float:
        """
        Calculate a total weighted score for placing an operation on a server at a given start time.
        Lower score is better.
        """
        server = self.inst.servers[server_id]
        op_cost = self._calculate_operation_cost(server_id, start_time, op.duration)
        potential_completion_time = start_time + op.duration

        delay = max(0, potential_completion_time - job.deadline)
        delay_penalty = delay * job.delay_weight * self.inst.weights["delay_penalty"]

        failure_penalty = 0
        if not server.is_cloud and self.inst.machine_failures:
            for f in self.inst.machine_failures:
                if f.machine_id == server_id:
                    # Check for overlap between operation and failure
                    overlap_start = max(start_time, f.failure_start)
                    overlap_end = min(start_time + op.duration, f.failure_end)

                    if overlap_end > overlap_start:
                        # Calculate effective capacity reduction at overlap_start
                        time_since_failure_start = max(0, overlap_start - f.failure_start)
                        failure_factor = 1.0 - math.exp(-f.failure_rate * time_since_failure_start)
                        effective_reduction_at_overlap = f.capacity_reduction * failure_factor

                        # Apply penalty based on how much capacity is effectively lost for this operation
                        # and how critical the job is.
                        # This aims to represent the risk of the operation being impacted or needing relocation.
                        # Penalty is proportional to the fraction of capacity lost for the op * delay penalty weight.
                        # Ensure server.capacity is not zero to avoid division by zero
                        if server.capacity > 0:
                            capacity_impact_ratio = min(1.0, op.capacity_required / server.capacity)
                            failure_penalty += effective_reduction_at_overlap * capacity_impact_ratio * self.inst.weights["delay_penalty"]

        total_weighted_score = (op_cost * self.inst.weights["compute_cost"]) + delay_penalty + failure_penalty
        return total_weighted_score
