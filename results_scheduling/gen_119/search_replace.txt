<DESCRIPTION>
This change refines the tie-breaking logic when deciding between a local and a cloud server. Previously, if the objective cost and start time were identical for a local and a cloud option, the logic ambiguously or explicitly favored cloud. This is corrected to prioritize local servers (which are 5x cheaper) when all other evaluation metrics (objective cost, start time) are equal. This ensures that local resources are maximized before resorting to cloud, thereby minimizing overall compute cost while maintaining schedule validity and adherence to deadlines. The logic now:
1. Prefers cloud if it's strictly better (lower objective cost).
2. Prefers cloud if it has the same objective cost but an earlier start time.
3. If objective cost AND start time are equal, and a local option has been found, the local option is retained. Only if no local option has been identified yet (or the current chosen server is already a cloud server) will an equally performing cloud option be selected.
</DESCRIPTION>
