<cost_time_window_low_priority>
Introduce cost-time window awareness for low-priority jobs.

This modification enhances the `_find_best_local_slot` logic within the `JobShopScheduler` class. For `LOW` priority jobs, the scheduler will now consider a small lookahead window (e.g., 4 hours) to find local server slots that offer lower compute costs, even if it means a slightly later start time. This is beneficial for cost efficiency without significantly impacting critical deadlines, as low-priority jobs often have more slack.

For higher priority jobs, the original "earliest start first" logic is preserved to ensure minimal delays. The sorting criteria for local candidates are dynamically adjusted:
- For `CRITICAL`/`HIGH`/`MEDIUM` jobs: prioritize the absolute earliest available start time, then lowest cost, then highest remaining capacity.
- For `LOW` jobs: within the defined lookahead window, prioritize lowest cost, then earliest start time, then highest remaining capacity.

This balances the need for speed for critical workloads with the opportunity for cost savings for less urgent tasks, leveraging the cost dynamics of the data center. A new `LOW_PRIORITY_COST_LOOKAHEAD_WINDOW` class attribute is added to control the search depth for cost optimization.

            # For high priorities: search for the absolute earliest slot starting from `earliest_start`.
            # For low priorities: search within `earliest_start` up to `earliest_start + LOW_PRIORITY_COST_LOOKAHEAD_WINDOW`.
