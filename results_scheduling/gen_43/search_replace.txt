<DESCRIPTION>
This edit refines the scheduling logic within `construct_schedule` to implement a more strategic server selection, explicitly prioritizing the overall objective function (`compute_cost + 5 × delay_penalty`).

Key improvements:

1.  **Objective-driven Local Server Selection**:
    *   When searching for a local slot, the algorithm first aims to find the *earliest possible start time* that satisfies capacity constraints and doesn't explicitly exceed the job's deadline *if a local machine can meet it*.
    *   Among all local slots that offer this `earliest_start_time` (or an equally good one up to the implicit deadline cap), it then chooses the specific server and start time that minimize the calculated `_get_op_schedule_cost` (which encapsulates both compute cost and estimated future delay penalties). This prevents choosing a slightly earlier slot if it results in a much higher cost without significant deadline benefit, while still valuing timeliness.

2.  **Optimal Cloud Server Selection**:
    *   The cloud option is now always considered as a direct alternative, not just a fallback for local unavailability.
    *   It determines the best cloud server by iterating through all compatible cloud machines and selecting the one that offers the minimum `_get_op_schedule_cost` starting at `current_op_start_time`. This ensures that even when using cloud, the most cost-effective cloud resource is chosen.

3.  **Unified Local vs. Cloud Decision**:
    *   After evaluating the best local option and the best cloud option separately, a direct comparison of their `_get_op_schedule_cost` determines the final scheduling decision. This provides a clean, objective-aligned trade-off between local and cloud resources, favoring the overall lowest cost solution.
    *   The `latest_start_time_to_meet_deadline` is used to guide the search window for local servers, ensuring that local search respects job deadlines as a primary consideration, with `_get_op_schedule_cost` guiding the optimal choice within that window.

This approach provides a more robust and cost-aware scheduling mechanism by systematically evaluating both local and cloud options against the multi-objective fitness function.
