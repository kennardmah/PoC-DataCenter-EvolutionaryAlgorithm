<DESCRIPTION>
This enhancement refines the local server selection logic by adding a third-level tie-breaking rule. After prioritizing the earliest start time and then the lowest compute cost, if multiple local servers still offer identical earliest start times and compute costs, the scheduler will now prefer the server that leaves the *most available capacity remaining* during the operation's entire duration. This is achieved by introducing a new helper function `_calculate_min_remaining_capacity` which determines the bottleneck capacity across the operation's span. By distributing load more evenly among local resources, this strategy aims to reduce future contention and subtly improve overall throughput, aligning with the "Capacity-Aware Placement" strategy.

    def _calculate_min_remaining_capacity(server_id: str, start: int, duration: int, capacity_req: int) -> int:
        """
        Calculates the minimum remaining capacity on a server over an operation's duration,
        after hypothetically scheduling the operation.
        """
        min_rem_cap = inst.servers[server_id].capacity + 1 # Initialize with a value higher than any possible capacity
        for t in range(start, start + duration):
            # Check if within time horizon (though has_capacity should have ensured this)
            if t >= inst.time_horizon:
                return -float('inf') # Indicate an invalid state

            current_used = capacity_usage[server_id].get(t, 0)
            current_available_base = get_available_capacity(server_id, t) # This already includes failure
            remaining_after_this_op = current_available_base - (current_used + capacity_req)
            min_rem_cap = min(min_rem_cap, remaining_after_this_op)
        return int(min_rem_cap)
