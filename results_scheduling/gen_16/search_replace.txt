<unified_cost_evaluation>
This modification refactors the scheduling loop for each operation to use a unified cost evaluation strategy for both local and cloud machines. Instead of separately prioritizing local machines based on immediate cost and then conditionally considering cloud for deadline violations, all viable options (local server + start time, or cloud server + immediate start time) are now evaluated using the `_get_op_schedule_cost` function. This function considers both compute cost and the projected impact on the job's overall delay penalty, ensuring that every scheduling decision directly contributes to minimizing the `Total Cost = compute_cost + 5 × delay_penalty` objective. This makes the local/cloud trade-off more intelligent and integrated. The redundant `latest_start_time_to_meet_deadline` logic is removed as the `_get_op_schedule_cost` naturally handles delay penalties across the entire time horizon.
