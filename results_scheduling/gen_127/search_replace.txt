    def _calculate_min_free_capacity_during_op(server_id: str, start: int, duration: int, capacity_req: int, current_capacity_usage: Dict[str, Dict[int, int]]) -> int:
        """
        Calculates the minimum remaining free capacity on a server during an operation's execution,
        assuming the operation is placed there. A higher value indicates more resilience.
        """
        min_free_capacity = float('inf')
        for t in range(start, start + duration):
            # Boundary check
            if t < 0 or t >= inst.time_horizon * 2:
                return -1 # Indicate out of bounds/invalid, effectively no free capacity
            used_at_t = current_capacity_usage[server_id].get(t, 0)
            available_at_t = get_available_capacity(server_id, t)
            remaining_after_op = available_at_t - (used_at_t + capacity_req)
            min_free_capacity = min(min_free_capacity, remaining_after_op)
        return int(min_free_capacity)

<unify_operation_selection>
Refactors the operation selection logic to use a `candidate_placements` list, collecting all valid local and cloud options. This list is then sorted using a multi-criteria key:
1. Minimize objective cost.
2. Prefer local (False) over cloud (True) if costs are equal.
3. Minimize start time if costs and local/cloud preference are equal.
4. Maximize minimum free capacity during operation (for resilience) if all above are equal.
5. Deterministic tie-breaking by server ID.

This provides a more robust and consistent decision-making process for selecting the best operation placement, ensuring all relevant factors (cost, delay, machine type, start time, resilience) are considered with clear priorities. The previous iterative `if/else` logic was prone to subtle tie-breaking issues.
</unify_operation_selection>
