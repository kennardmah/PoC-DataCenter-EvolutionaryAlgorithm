<add_resilience_tie_breaker>
Introduces a tertiary tie-breaking mechanism for local server selection. When multiple local servers offer the same earliest start time and the same minimum compute cost for an operation, the scheduler will now prefer the server that maintains the highest minimum *free capacity* (available capacity minus current usage and projected failure-induced reductions) during the operation's entire duration. This aims to improve robustness, especially in failure scenarios, by proactively choosing more resilient machines to reduce the likelihood of future capacity violations and costly cloud relocations.
