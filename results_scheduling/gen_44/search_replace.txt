<DESCRIPTION>
This enhancement refines the `construct_schedule` function by integrating cost awareness into its earliest-available-slot scheduling logic.

**Motivation:** The previous approach prioritized local machines by earliest start time without considering hourly cost variations or multiple equally-early local slots. For cloud fallback, it simply picked the first compatible cloud server. This could lead to unnecessary costs if a cheaper local or cloud server could start at the same earliest time.

**Changes Introduced:**
1.  **`_calculate_operation_compute_cost` Helper:** A new helper function is introduced within `construct_schedule` to calculate the direct compute cost of an operation on a given server for a specific duration. This allows for explicit cost evaluation during scheduling decisions.
2.  **Local Server Tie-breaking:** When multiple local servers can accommodate an operation starting at the *same earliest time*, the scheduler now breaks ties by choosing the server that incurs the *lowest compute cost* for that operation. This directly addresses recommendation #1 and optimizes local resource utilization for cost efficiency when timing is not an issue.
3.  **Cloud Server Selection by Cost:** In scenarios where no local machine can be found within the available horizon, the scheduler now iterates through all compatible cloud servers and selects the one that offers the *lowest compute cost* for the immediate start. This addresses recommendation #4, ensuring that even when resorting to the higher-cost cloud, the most economical cloud option is chosen.

These changes are designed to improve the overall `compute_cost` component of the objective function while maintaining the primary goal of avoiding delays by favoring earliest start times and using cloud resources as a robust fallback.
