<priority_cost_aware_scheduler>
This modification overhauls the scheduling algorithm within `construct_schedule` to be significantly more intelligent, moving from a simple online FIFO to a priority and cost-aware heuristic.

**Key Changes:**

1.  **Job Prioritization**: Jobs are no longer scheduled purely by arrival time. Instead, they are sorted by an urgency metric that considers:
    *   **Priority Level**: CRITICAL jobs are highest, followed by HIGH, MEDIUM, then LOW.
    *   **Deadline Slack**: Jobs with less time between their estimated earliest completion and their deadline are prioritized.
    *   **Delay Weight**: Jobs with higher penalties for delays are also prioritized.
    *   **Arrival Time**: As a tie-breaker, earlier arriving jobs are still preferred.
    This helps ensure critical and urgent tasks are addressed promptly, minimizing delay penalties.

2.  **Cost-Aware Time Window Search**: For each operation within a job:
    *   It determines a flexible scheduling window: from `job_available_time` up to `inst.time_horizon` or a calculated `latest_start_time_to_meet_deadline`.
    *   It iterates through all compatible *local* servers and, for each server, searches within this window for the *cheapest* possible start time that satisfies capacity constraints and doesn't violate the job's deadline. The hourly cost of the server is directly incorporated into this decision.
    *   It keeps track of the best local option found (server and start time) based on minimum cost.

3.  **Smart Local/Cloud Trade-off**:
    *   After evaluating all local options, if a feasible local slot is found, it is preferred to minimize `compute_cost`.
    *   If no local slot is found within the feasible time window, or if the best local slot would still push the job past its deadline, then a cloud server is immediately considered. Cloud servers offer unlimited capacity and are chosen as a fallback to prevent deadline violations, despite their higher cost.
    *   This balances the objective of minimizing `compute_cost` (by using local) with minimizing `delay_penalty` (by using cloud when local is insufficient).

4.  **Capacity-Aware Placement**: By iterating through available servers and checking `has_capacity` for each time slot, the scheduler is more aware of the current and projected load on machines, helping to distribute tasks and avoid bottlenecks where possible.

These improvements aim to reduce both `compute_cost` by making smarter local machine choices and `delay_penalty` by prioritizing urgent jobs and intelligently using cloud resources as a last resort.
