<adaptive_cloud_fallback_low_priority>
Refined local search window for LOW priority jobs to enable faster cloud fallback.

This modification implements an "Adaptive Cloud Fallback Trigger for Low Priority Jobs." For jobs classified as 'LOW' priority, the scheduler will only search for a local machine slot within a limited time window (e.g., `current_op_start_time + LOW_PRIORITY_LOCAL_SEARCH_WINDOW`). If no local slot is found within this short window, the operation will immediately fall back to a cloud server. This strategy aims to:
1.  **Preserve Local Capacity**: Prevent low-priority jobs from consuming valuable local machine capacity that might be needed by higher-priority jobs, especially if they would occupy the machine for a long time far into the future.
2.  **Reduce Search Overhead**: Speed up scheduling decisions for low-priority tasks by not performing an exhaustive search across the entire time horizon.
3.  **Optimize Cost/Delay Trade-off**: For low-priority jobs, a slight increase in compute cost (by moving to cloud) might be acceptable if it prevents potential delays or contention for critical local resources. The immediate cloud fallback prioritizes timely execution for these non-critical tasks without exhaustive local search.

By making this change, the scheduler becomes more dynamic and resource-aware, ensuring that high-priority jobs have a better chance at securing optimal local slots, while low-priority jobs are processed efficiently, even if it means incurring a higher cloud cost in specific scenarios.
