<DESCRIPTION>
This enhancement refines the operation scheduling logic within `construct_schedule` by introducing a cost-aware and failure-proactive slot selection mechanism. Instead of a simple "first available local, then cloud" greedy approach, it now evaluates potential slots on all compatible servers (local and cloud) and selects the one that minimizes a combined weighted score.

**Key Improvements:**
1.  **Unified Slot Search**: A single loop evaluates all compatible local and cloud servers and their available start times.
2.  **Multi-Criteria Slot Selection**: For each potential `(server, start_time)` combination, a "total weighted score" is calculated. This score incorporates:
    *   **Compute Cost**: The actual hourly cost for the operation's duration on that server (`_calculate_operation_cost`).
    *   **Delay Penalty**: The impact of the operation's completion time on the job's deadline, weighted by `job.delay_weight`.
    *   **Failure Penalty (Local Only)**: A heuristic penalty applied to local machines if the operation's execution window overlaps with a known machine failure. This encourages the scheduler to proactively avoid machines with forecasted instabilities, balancing immediate cost with resilience. The penalty is proportional to the capacity reduction and duration of overlap.
3.  **Prioritized Selection**: The scheduler chooses the slot with the lowest `total_weighted_score`. If scores are equal, it prioritizes local servers over cloud, then earlier start times, and finally server ID for deterministic tie-breaking.
4.  **Dedicated Cost Calculation Helper**: A new helper function `_calculate_operation_cost` is introduced to encapsulate the logic for computing the monetary cost of an operation, which is used consistently for both local and cloud options.

These changes allow the scheduler to make more informed decisions, directly addressing the multi-objective goal of minimizing `Total Cost = compute_cost + 5 × delay_penalty` while enhancing robustness in failure scenarios. The lookahead for finding a slot is kept within `inst.time_horizon` to prevent scheduling beyond the evaluation window.

    def _calculate_operation_cost(server_id: str, start: int, duration: int) -> float:
        """Calculate the compute cost for an operation."""
        cost = 0.0
        for t in range(start, start + duration):
            if t >= inst.time_horizon: # Ensure not to calculate cost beyond the time horizon
                break
            cost += inst.server_cost[server_id][t % inst.time_horizon]
        return cost
