<DESCRIPTION>
This edit refines the `_calculate_operation_objective_value` and the main `run_scheduling` loop for improved decision-making.

**`_calculate_operation_objective_value` changes:**
1.  **Corrected Objective Weighting:** Explicitly uses `self.inst.weights['compute_cost']` and `self.DELAY_PENALTY_WEIGHT_IN_OBJECTIVE` to accurately reflect the problem's total cost formula: `Total Cost = compute_cost + 5 × delay_penalty`. The previous version implicitly assumed `inst.weights` contained `1` and `5` respectively, which is not guaranteed.
2.  **Same-Server Chaining Bonus:** Introduces a `CHAINING_BONUS_COST_REDUCTION` (set to 10.0, tunable) that is applied to the objective cost if a CRITICAL or HIGH priority job can continue on the same local server as its previous operation. This incentivizes efficient resource utilization and reduces overheads for important jobs.
3.  **Resilience Bonus:** Incorporates a `RESILIENCE_BONUS_FACTOR` (0.5, tunable) that rewards scheduling on local servers with more minimum free capacity during an operation's execution. This makes the scheduler prefer more robust local allocations, especially amplified for CRITICAL jobs, aligning with failure resilience goals.

**`run_scheduling` changes:**
1.  **Refined Tie-breaking:** The logic for selecting between local and cloud options is simplified by creating a comprehensive tie-breaking tuple that includes objective cost, start time, whether it's a cloud server, a chaining score, negative minimum free capacity (for resilience), and server ID. This tuple allows for a single comparison to determine the best option, making the decision process more robust and easier to understand.
2.  **`last_scheduled_local_server_per_job` management:** The `last_scheduled_local_server_per_job` attribute is now correctly updated after each operation is scheduled and used to calculate the `preferred_for_chaining_server` for the next operation. This ensures the chaining bonus is applied correctly.
3.  **Dynamic Search Window Integration:** Properly integrates the `PRIORITY_SEARCH_WINDOW_FACTORS` to dynamically adjust the `search_end_time` for local machine searches based on job priority, as defined in the `__init__` method in the previous step. This balances finding cheaper off-peak slots for low-priority jobs with ensuring timely completion for high-priority ones.
4.  **Optimized Cloud Selection:** For cloud servers, it now correctly finds the cheapest available cloud server among compatible types before calculating its full objective value, ensuring cost efficiency for cloud usage.

            """
            Calculates the estimated total objective cost of scheduling an operation on a given server
            at a given start time. This includes compute cost and an estimate of future delay penalty
            for the entire job, aligning with the problem's total cost objective.
            """
            # Calculate compute cost for this operation
            op_compute_cost = 0.0
            for t in range(start_time, start_time + op_duration):
                # Ensure time index for cost is within time_horizon
                cost_t = t % self.inst.time_horizon
                op_compute_cost += self.inst.server_cost[server_id][cost_t]

            # Estimate remaining duration of the job after this operation
            remaining_operations_duration = sum(o.duration for o in job_obj.operations[op_idx + 1:])

            # Projected job completion time if this operation finishes at start_time + op_duration
            # and all subsequent operations start immediately
            projected_job_completion_time = (start_time + op_duration) + remaining_operations_duration

            # Calculate potential delay penalty for the entire job based on projected completion
            projected_delay = max(0, projected_job_completion_time - job_obj.deadline)

            delay_penalty_contribution = projected_delay * job_obj.delay_weight * self.inst.weights['delay_penalty']

            # Total score to minimize for this operation's placement
            return (op_compute_cost * self.inst.weights['compute_cost']) + delay_penalty_contribution
