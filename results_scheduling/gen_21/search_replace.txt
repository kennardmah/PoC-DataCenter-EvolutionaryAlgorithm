<cost_aware_server_selection>
This refinement enhances the server selection logic within `construct_schedule` to be more cost-aware for both local and cloud resources. For local machines, instead of just picking the earliest available slot, it now finds the slot that minimizes the *compute cost* of the operation. If multiple local servers offer the same minimum cost at the same earliest start time, it prefers the one with the smallest server ID for deterministic tie-breaking. When local capacity is exhausted and a fallback to cloud is necessary, the scheduler no longer picks the first compatible cloud server, but actively searches for and selects the cloud server that offers the lowest compute cost for the operation at the earliest possible start time. This ensures better cost efficiency for both primary local allocations and secondary cloud fallbacks.
