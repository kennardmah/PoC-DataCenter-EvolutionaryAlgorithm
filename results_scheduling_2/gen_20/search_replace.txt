<DESCRIPTION>
This edit refines the online scheduling heuristic by implementing a more sophisticated conditional cloud fallback mechanism (Recommendation 5). The previous attempt to apply this failed due to a `SEARCH` block mismatch; this version ensures the `SEARCH` block is exact.

The key changes are:
1.  **Modified `operation_objective` return value**: It now returns a tuple `(total_objective_cost, projected_job_completion_time)`. This enables the `schedule_job_online` function to use the estimated full job completion time for more intelligent deadline-aware decision-making.
2.  **Constants for Cloud Override**: Introduced `CLOUD_OVERRIDE_DELAY_THRESHOLD` (e.g., 2 hours past deadline) and `CLOUD_OVERRIDE_COST_FACTOR` (e.g., cloud cost can be up to 1.5x local cost for override). These are configurable parameters to tune the aggressiveness of cloud adoption for urgent jobs.
3.  **Separate Tracking of Best Options**: Within `schedule_job_online`, we now keep track of the `best_overall_candidate`, `best_local_candidate`, and `best_cloud_candidate` for the current operation. Each candidate tuple stores `(objective_cost, projected_job_completion_time, operation_start_time, server_id, is_cloud_flag)`. This richer information allows for more nuanced comparisons.
4.  **Conditional Cloud Override Logic**:
    *   After evaluating all potential slots (local and cloud) for the current operation, the scheduler checks specific conditions for a "cloud override."
    *   **Condition 1 (Urgency)**: If the *best available local option* for the current operation would result in the *entire job* completing significantly past its deadline (threshold defined by `CLOUD_OVERRIDE_DELAY_THRESHOLD`).
    *   **Condition 2 (Feasibility/Benefit)**: If the *best available cloud option* can complete the *entire job* earlier than the best local option *and* its overall objective cost is not excessively higher than the *best local option* (factor defined by `CLOUD_OVERRIDE_COST_FACTOR`).
    *   If both conditions for the cloud override are met, the cloud option is chosen, explicitly prioritizing timely job completion to avoid severe delay penalties. Otherwise, the default choice remains the `best_overall_candidate` that minimizes the objective function, respecting tie-breaking rules (cost, then earlier completion time, then earlier operation start time, then server ID, then prefer local over cloud).

This strategy aims to provide a more robust response to impending deadline violations and capacity constraints, especially during emergency scenarios, by leveraging cloud capacity aggressively when local resources cannot meet urgent demands in a timely fashion, thereby reducing overall delay penalties while managing costs within a defined tolerance.

def operation_objective(inst, server_id, start, op, job, current_op_idx, all_job_operations, hypothetical_capacity_usage, is_cloud: bool):
    current_op_compute_cost_raw = sum(inst.server_cost[server_id][t % inst.time_horizon]
                                      for t in range(start, start + op.duration))

    current_op_cloud_cost_raw = 0
    if is_cloud:
        current_op_cloud_cost_raw = CLOUD_DETERRENCE_PER_HOUR * op.duration

    # Simulate future operations to get a realistic projected completion time and future cost
    simulated_future_compute_cost_raw, simulated_job_completion, simulated_future_cloud_cost_raw = \
        _simulate_remaining_ops_cost_and_time(
            inst, job, start + op.duration, current_op_idx, hypothetical_capacity_usage
        )

    total_compute_cost_raw = current_op_compute_cost_raw + simulated_future_compute_cost_raw
    total_cloud_deterrence_raw = current_op_cloud_cost_raw + simulated_future_cloud_cost_raw

    # Project the overall job completion time (including the current op and simulated future ops)
    projected_completion = simulated_job_completion
    delay = max(0, projected_completion - job.deadline)

    priority_multiplier = PRIORITY_WEIGHTS.get(job.priority, 1.0) # Default to 1.0 for unknown priorities

    # Apply priority multiplier to all cost components
    compute_cost_weighted = total_compute_cost_raw * inst.weights['compute_cost'] * priority_multiplier
    delay_penalty_weighted = delay * job.delay_weight * inst.weights['delay_penalty'] * priority_multiplier
    cloud_deterrence_weighted = total_cloud_deterrence_raw * inst.weights['compute_cost'] * priority_multiplier # Apply to cloud deterrence too

    total_cost = compute_cost_weighted + delay_penalty_weighted + cloud_deterrence_weighted

    return total_cost
