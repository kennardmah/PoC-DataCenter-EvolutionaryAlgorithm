<best_fit_local_search>
Introduce a "best-fit" heuristic for local servers instead of "first-fit." Previously, the scheduler would take the very first available time slot it found on any local server that matched the operation type. This edit modifies the logic so that for each compatible local server, the scheduler searches its entire specified horizon (up to `job.deadline + inst.time_horizon`) to find the *single best* time slot that minimizes the calculated objective cost. This "best-fit on server" candidate is then compared against all other local server candidates and any available cloud options, and the overall best is chosen. This change allows the scheduler to make more informed decisions about local resource allocation, potentially leading to better resource utilization and lower overall costs by avoiding suboptimal early placements.
