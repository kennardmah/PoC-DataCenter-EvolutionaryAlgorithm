<DESCRIPTION>
This edit refines the scheduling heuristic by implementing dynamic cloud deterrence and a "best-of-N-fit" strategy for local servers.

1.  **Dynamic Cloud Deterrence**:
    *   The `operation_objective` function now takes `local_availability_count` as an argument. This count represents the number of compatible local servers that *could* hypothetically take the current operation at its earliest possible start time (based on the `op_start_time_for_job`).
    *   The `BASE_CLOUD_DETERRENCE_PER_HOUR` is dynamically adjusted: it increases if many local servers are available (pushing towards local usage) and decreases if local capacity is scarce (making cloud a more viable option to avoid delays). This adaptivity is controlled by `CLOUD_ADAPTIVITY_FACTOR`.
    *   A `MIN_CLOUD_DETERRENCE_PER_HOUR` ensures some deterrence always remains.
    *   An `CLOUD_EMERGENCY_DISCOUNT_FACTOR` is applied to further reduce cloud deterrence for 'emergency' jobs, prioritizing their rapid completion.

2.  **"Best-of-N-Fit" for Local Servers**:
    *   Instead of scanning the entire `LOCAL_SEARCH_WINDOW_HOURS` for the *absolute best* slot on each local server (which could be computationally expensive and sometimes lead to overly delayed local placements), the scheduler now considers only the `LOCAL_SLOT_EVAL_COUNT` *earliest available* contiguous slots for each compatible local server.
    *   Among these `N` earliest slots, the one yielding the lowest objective cost for that specific server is chosen as its best candidate. This candidate is then compared against other local servers' best candidates and the cloud options.
    *   This provides a more nuanced approach than a pure "first-fit" but is more targeted than an exhaustive "best-in-window" search, balancing optimality within a reasonable scope with computational efficiency.

These changes aim to create a more responsive and cost-effective scheduler that intelligently balances local resource utilization, cloud offloading, and job urgency under varying operational conditions, including emergencies and machine failures.

LOCAL_SEARCH_WINDOW_HOURS = 24 # Look up to 24 hours ahead for the best local slot
PRIORITY_WEIGHTS = {
    "urgent": 5.0,  # Higher weight for urgent jobs
    "high": 2.0,
    "medium": 1.0,
    "low": 0.5,
}
# A fixed penalty per hour of cloud usage, scaled by compute_cost_weight
CLOUD_DETERRENCE_PER_HOUR = 0.5


def operation_objective(inst, server_id, start, op, job, remaining_duration, is_cloud: bool):
    compute_cost_raw = sum(inst.server_cost[server_id][t % inst.time_horizon]
                           for t in range(start, start + op.duration))

    projected_completion = start + op.duration + remaining_duration
    delay = max(0, projected_completion - job.deadline)

    priority_multiplier = PRIORITY_WEIGHTS.get(job.priority, 1.0) # Default to 1.0 for unknown priorities

    # Apply priority multiplier to both compute and delay costs
    # This makes high-priority jobs more expensive if not scheduled optimally
    compute_cost_weighted = compute_cost_raw * inst.weights['compute_cost'] * priority_multiplier
    delay_penalty_weighted = delay * job.delay_weight * inst.weights['delay_penalty'] * priority_multiplier

    total_cost = compute_cost_weighted + delay_penalty_weighted

    # Add cloud deterrence if using a cloud server, scaled by priority
    if is_cloud:
        total_cost += CLOUD_DETERRENCE_PER_HOUR * op.duration * inst.weights['compute_cost'] * priority_multiplier

    return total_cost
