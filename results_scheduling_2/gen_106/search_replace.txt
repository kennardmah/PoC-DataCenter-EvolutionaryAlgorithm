<DESCRIPTION>
This edit refines the local server search window by introducing dynamic bounds based on job characteristics and global instance parameters. It directly addresses **Recommendation 5 (Prioritized and Slightly Expanded Search Window for Critical Jobs)** and enhances consistency in the lookahead simulation.

Key changes:
1.  **New Tunable Parameters**: Introduced `DEFAULT_LOCAL_SEARCH_LOOKAHEAD_HOURS`, `DEADLINE_BASED_LOOKAHEAD_FACTOR`, and `CRITICAL_JOB_EXTRA_LOOKAHEAD_HOURS` to control the search window behavior.
2.  **Dynamic Search Window for Local Servers**:
    *   In `schedule_job_online`, the upper bound for the local server search (`search_end_time`) is now calculated more intelligently. It considers a minimum lookahead from the operation's start time, extends up to a point relative to the job's deadline, and then adds extra lookahead for 'emergency' or 'high' priority jobs. This allows critical jobs to explore a wider range of local slots to find a more optimal, less costly solution.
    *   This dynamic window is capped by `inst.time_horizon` to prevent unbounded searches, which is especially important as job deadlines can be very far in the future.
3.  **Consistent Simulation Lookahead**: The `_simulate_remaining_ops_cost_and_time` function now uses the *same dynamic search window logic*. This ensures that the projected future costs and completion times used in the `operation_objective` are based on a more realistic and consistent application of the scheduling policy, improving the accuracy of objective calculations.

This approach balances the need to find good local slots for all jobs with a strategic expansion for high-priority tasks, aiming to reduce overall cost and delay penalties by leveraging local resources more effectively, especially during critical periods.
</DESCRIPTION>
