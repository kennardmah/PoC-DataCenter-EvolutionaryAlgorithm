<DESCRIPTION>
This edit implements a "Best-of-N-First-Fit" local search heuristic for local servers, inspired by recommendation #1.

The previous approach for local servers was a pure "first-fit" (i.e., `break` after finding the first available slot). This modification introduces a slightly deeper, yet still efficient, search strategy:

1.  **`LOCAL_SEARCH_N_BEST_SLOTS` Parameter**: A new constant `LOCAL_SEARCH_N_BEST_SLOTS` is introduced (set to 3). This determines how many of the "best" available slots on a local server will be considered.
2.  **Extended Local Server Search**: For each compatible local server, instead of stopping at the first available slot, the scheduler now iterates through *all* valid start times within the `search_end_time` window.
3.  **Collection of Best Slots per Server**: During this iteration, it continuously tracks and updates a list of up to `LOCAL_SEARCH_N_BEST_SLOTS` lowest-cost valid placements found so far *for that specific local server*.
4.  **Server-Specific Best Selection**: After thoroughly searching all possible start times for a given local server, the single best option from the `N` collected candidates for *that server* is selected.
5.  **Global Comparison**: This best "local server" option is then compared against the current global `best_op_candidate` (which includes cloud options and options from other local servers) to determine the overall optimal placement.

This heuristic aims to improve resource utilization and overall cost-efficiency by allowing local servers to find slightly better (potentially non-first) slots without incurring the full computational cost of an exhaustive search. It strikes a balance between greedy immediate placement and a more informed decision for local resources, while still respecting the online scheduling constraints.

PRIORITY_WEIGHTS = {
    "emergency": 8.0,  # Highest urgency, highest penalty for delay
    "high": 3.0,
    "medium": 1.0,
    "low": 0.5,
}
# A fixed penalty per hour of cloud usage, scaled by compute_cost_weight and priority
CLOUD_DETERRENCE_PER_HOUR = 0.5


def _calculate_placement_score(inst: Instance, server_id: str, start: int, op: Operation, job: Job, remaining_duration: int, is_cloud: bool) -> float:
    """
    Calculates a weighted score for a proposed operation placement,
    considering compute cost, the impact on the job's overall delay penalty,
    and dynamic cloud deterrence based on priority.
    """
    # Compute cost for THIS operation
    op_compute_cost_raw = sum(inst.server_cost[server_id][t % inst.time_horizon]
                              for t in range(start, start + op.duration))

    # Projected completion time for THE ENTIRE JOB
    projected_op_end = start + op.duration
    projected_job_completion = projected_op_end + remaining_duration

    # Calculate the delay penalty for THE ENTIRE JOB.
    delay = max(0, projected_job_completion - job.deadline)

    # Apply priority multiplier to the delay penalty.
    priority_factor = PRIORITY_WEIGHTS.get(job.priority, 1.0)
    delay_penalty = delay * job.delay_weight * priority_factor * inst.weights['delay_penalty']

    # Apply priority multiplier to compute cost as well
    compute_cost_weighted = op_compute_cost_raw * inst.weights['compute_cost'] * priority_factor

    total_cost = compute_cost_weighted + delay_penalty

    # Add cloud deterrence if using a cloud server, scaled by priority
    if is_cloud:
        total_cost += CLOUD_DETERRENCE_PER_HOUR * op.duration * inst.weights['compute_cost'] * priority_factor

    # Tie-breaker: prefer earlier starts slightly if costs are otherwise equal
    total_cost += start * 0.0001

    return total_cost
