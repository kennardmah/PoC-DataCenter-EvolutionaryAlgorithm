<DESCRIPTION>
This edit introduces a dynamic cloud deterrence factor that adapts based on the available local capacity for the specific operation's machine type.

**Rationale:**
The previous versions used a fixed `CLOUD_DETERRENCE_BASE`. However, the cost-effectiveness of local machines versus cloud machines changes depending on the current load and availability of local resources.
1.  **Avoid Unnecessary Cloud Usage**: When local machines have plenty of available capacity, we want to strongly encourage using them due to their lower base cost. Increasing cloud deterrence in such scenarios pushes jobs to local machines, saving costs.
2.  **Ensure Responsiveness During Local Congestion/Failures**: When local machines are highly utilized or impacted by failures, forcing jobs to wait for distant future slots can lead to high delay penalties, especially for high-priority jobs. In these situations, cloud should become a more attractive fallback. By *reducing* cloud deterrence when local capacity is scarce, we allow jobs to more readily "burst" to the cloud, mitigating delays and improving overall scores, particularly during earthquake scenarios.

**Mechanism:**
A new helper function, `_get_local_capacity_utilization_factor`, is introduced. For a given operation type and a proposed start time, it calculates an "effective utilization" for local machines of that type over the operation's duration.
- If local machines are mostly idle, the factor is low, resulting in a *higher* effective cloud deterrence.
- If local machines are heavily used or have reduced capacity, the factor is high, resulting in a *lower* effective cloud deterrence.

This `effective_cloud_deterrence_base` is then passed to `_calculate_placement_score`. This makes the decision-making more adaptive to the current state of the local infrastructure.

**New parameters:**
-   `CLOUD_DETERRENCE_ADAPTATION_STRENGTH`: Controls how aggressively cloud deterrence adapts to local utilization (higher value means stronger adaptation).
-   `MIN_CLOUD_DETERRENCE_FACTOR`: Ensures a minimum deterrence is always applied, preventing cloud from becoming too cheap even when local machines are overwhelmed.
