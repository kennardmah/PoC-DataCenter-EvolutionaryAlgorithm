<new_heuristics>
This update introduces several heuristics to improve online scheduling performance:

1.  **Adaptive Local Search Window**: The search horizon for finding available slots on local machines is now dynamic. For high-priority and emergency jobs, the window is narrowed (or kept relatively small) to encourage faster placement, even if it means resorting to cloud resources sooner. For lower-priority jobs, the window can be expanded to allow for a broader search for more cost-effective local slots, optimizing resource utilization over time. This balances urgency with cost-efficiency.

2.  **Estimated Future Compute Costs**: The objective function for evaluating operation placements now considers not just the current operation's cost, but also a discounted estimate of the compute costs for *all subsequent operations* within the same job. This estimate assumes these future operations would run on the cheapest available cloud server of their respective types. This provides a more holistic, job-level cost perspective, encouraging decisions that lead to lower overall job expenditure rather than just optimizing the current operation in isolation.

3.  **Refined Tunable Parameters & Structure**: Tunable parameters for priority multipliers, cloud deterrence, and search window adjustments are centralized and adjusted within the nested `OperationPlacementEvaluator` class. This improves clarity and makes future tuning easier. The `CLOUD_DETERRENCE_BASE` is slightly increased, and `PRIORITY_MULTIPLIERS` are fine-tuned. A `FUTURE_CLOUD_COST_DISCOUNT_FACTOR` is added to reflect that future costs are estimates and less certain.

These modifications aim to create a more intelligent scheduler that is more responsive to job urgency, more aware of total job costs, and better able to manage the local vs. cloud tradeoff under dynamic conditions.

        def _calculate_placement_score(
            self,
            job_ref: Job,
            operation: Operation,
            proposed_start: int,
            server_id: str,
            is_cloud_server: bool,
            remaining_ops_duration: int,
            _cloud_deterrence_override_factor: float = 1.0
        ) -> float:
            """
            Calculates a weighted score for a proposed operation placement.
            """
            # Compute cost for THIS operation
            op_compute_cost = sum(self.inst.server_cost[server_id][t % self.inst.time_horizon]
                                  for t in range(proposed_start, proposed_start + operation.duration))

            # Add cloud deterrence if the operation is placed on a cloud server.
            if is_cloud_server:
                deterrence = self.CLOUD_DETERRENCE_BASE
                if job_ref.priority == 'emergency':
                    deterrence *= (1.0 - self.CLOUD_EMERGENCY_DISCOUNT_FACTOR)

                deterrence *= _cloud_deterrence_override_factor
                op_compute_cost += deterrence

            # Projected completion time for THE ENTIRE JOB
            projected_op_end = proposed_start + operation.duration
            projected_job_completion = projected_op_end + remaining_ops_duration

            # Calculate the delay penalty for THE ENTIRE JOB.
            delay = max(0, projected_job_completion - job_ref.deadline)

            # Apply priority multiplier to the delay penalty.
            priority_factor = self.PRIORITY_MULTIPLIERS.get(job_ref.priority, 1.0)
            delay_penalty = delay * job_ref.delay_weight * priority_factor * self.inst.weights['delay_penalty']

            # Total score for this specific operation placement.
            total_score = (
                op_compute_cost * self.inst.weights['compute_cost']
                + delay_penalty
            )

            # Tie-breaker: prefer earlier starts slightly if costs are otherwise equal.
            total_score += proposed_start * 0.0001

            return total_score

                deterrence *= _cloud_deterrence_scale_factor
                op_compute_cost += deterrence

            # Estimate future compute costs for remaining operations
            estimated_future_compute_cost = 0
            for rem_op in remaining_ops:
                cheapest_cloud_cost_per_hour = self.cheapest_cloud_costs_per_type[rem_op.server_type]
                estimated_future_compute_cost += cheapest_cloud_cost_per_hour * rem_op.duration * self.FUTURE_CLOUD_COST_DISCOUNT_FACTOR

            projected_op_end = proposed_start + operation.duration
            projected_job_completion = projected_op_end + sum(o.duration for o in remaining_ops)

            delay = max(0, projected_job_completion - job_ref.deadline)
