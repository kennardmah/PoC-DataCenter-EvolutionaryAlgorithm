<adaptive_window_and_cloud_trigger_v2>
This refined scheduling heuristic dynamically adjusts the local machine search window based on job priority and deadline proximity. It also introduces a "critical delay" trigger to significantly reduce cloud deterrence, making cloud more attractive when local options would cause a severe deadline miss.

Key changes:
-   **New Configurable Parameters**: Introduced `PRIORITY_WINDOW_FACTORS`, `BASE_LOCAL_SEARCH_WINDOW`, `DEADLINE_PROXIMITY_WINDOW_REDUCTION_FACTOR`, and `CRITICAL_DELAY_THRESHOLD_HOURS` for fine-tuning the algorithm's behavior.
-   **Adaptive Local Search Window**: The `MAX_LOCAL_SEARCH_WINDOW` is now dynamically calculated based on job priority (shorter for urgent jobs, longer for less urgent ones) and further reduced if the job is already projected to miss its deadline. This ensures that critical jobs make faster decisions while allowing less critical ones to explore cheaper local options.
-   **Dynamic Cloud Deterrence for Criticality**: The `_calculate_placement_score` function now accepts a dynamically computed `_current_cloud_deterrence`. This deterrence is significantly reduced if the best available local slot would lead to the *entire job* exceeding a `CRITICAL_DELAY_THRESHOLD_HOURS` past its deadline. This makes cloud a highly attractive fallback for critical deadline misses, balancing cost with urgency.
-   **Return Delay from Score Function**: The `_calculate_placement_score` now returns both the calculated score and the projected delay. This allows the main scheduling logic to use the projected delay for making informed decisions about cloud deterrence.
-   **Improved Best Option Tracking**: Explicitly tracks `best_local_score`, `best_local_placement`, and `best_local_projected_delay` to correctly assess the impact of local options before making a final choice, especially for triggering dynamic cloud deterrence.

These changes aim to optimize the trade-off between local cost savings and timely completion of high-priority and deadline-sensitive jobs, making the scheduler more robust in varying scenarios, including emergencies.

    # Define priority multipliers for delay penalties
    # Tuned to make higher priorities significantly more sensitive to delays.
    # Emergency jobs will incur a much higher cost if delayed.
    PRIORITY_MULTIPLIERS = {
        'emergency': 8.0, # Highest urgency, highest penalty for delay
        'high': 3.0,
        'medium': 1.0,
        'low': 0.5,       # Lowest urgency, more flexible with delay
    }

    CLOUD_DETERRENCE_BASE = 75.0

    # making cloud a more palatable option for urgent tasks.
    CLOUD_EMERGENCY_DISCOUNT = 0.8 # Reduce cloud deterrence by 80% for emergency jobs

        _inst: Instance,

        _server_id: str,
        _is_cloud_server: bool,
        _remaining_ops_duration: int,
        _priority_multipliers: Dict[str, float],
        _cloud_deterrence_base: float,
        _cloud_emergency_discount: float
    ) -> float:
        """
        Calculates a weighted score for a proposed operation placement,
        considering compute cost, the impact on the job's overall delay penalty,
        and adding dynamic cloud deterrence.
        """
        # Compute cost for THIS operation
        op_compute_cost = sum(_inst.server_cost[_server_id][t % _inst.time_horizon]
                              for t in range(_proposed_start, _proposed_start + _operation.duration))

        # Add cloud deterrence if the operation is placed on a cloud server.
        if _is_cloud_server:
            deterrence = _cloud_deterrence_base
            if _job.priority == 'emergency':
                # Apply discount for emergency jobs to prioritize their speed.
                deterrence *= (1.0 - _cloud_emergency_discount)
            op_compute_cost += deterrence

        # Projected completion time for THE ENTIRE JOB if this operation starts at _proposed_start.
        projected_op_end = _proposed_start + _operation.duration
        projected_job_completion = projected_op_end + _remaining_ops_duration

        # Calculate the delay penalty for THE ENTIRE JOB.
        delay = max(0, projected_job_completion - _job.deadline)

        # Apply priority multiplier to the delay penalty to reflect job urgency.
        priority_factor = _priority_multipliers.get(_job.priority, 1.0)
        delay_penalty = delay * _job.delay_weight * priority_factor * _inst.weights['delay_penalty']

        # Total score for this specific operation placement.
        total_score = (
            op_compute_cost * _inst.weights['compute_cost']
            + delay_penalty
        )

        # A small positive coefficient for proposed_start ensures that given two options
        # with identical weighted cost, the one starting earlier is preferred, promoting flow.

        return total_score
