<DESCRIPTION>
This edit refines the online scheduling heuristic by implementing a more sophisticated lookahead mechanism for evaluating operation placements. Instead of simply summing the durations of remaining operations, the scheduler now performs a greedy simulation of subsequent operations for a given job for each candidate placement of the *current* operation.

For each candidate placement of the current operation on a specific server at a specific start time:
1.  A temporary snapshot of the current capacity usage is created, and the *current* operation is hypothetically placed into it.
2.  A new helper function, `_simulate_greedy_future_ops`, is then called. This function takes the remaining, unscheduled operations for the job and the `capacity_usage` snapshot (which now includes the current operation). It iteratively and greedily schedules each subsequent operation, finding the earliest available slot on either a local or cloud machine (prioritizing local based on a slightly modified cost to prefer them, but always considering cloud as a fallback). It builds upon the simulated capacity usage as it places each subsequent operation.
3.  `_simulate_greedy_future_ops` returns the accumulated compute cost for these simulated future operations and the projected final completion time of the entire job.
4.  The `_calculate_placement_score` function utilizes these simulated costs and completion times, combining them with the current operation's cost and the job's overall delay penalty (which is now based on a more accurate total completion time projection). Cloud deterrence is also applied to the *current* operation within this function.

This change directly addresses **Recommendation 4: Refine Lookahead Simulation with Greedy Subsequent Operation Placement**, aiming to improve the scheduler's decision-making by providing a more accurate foresight into the total impact of a single operation's placement on the entire job's cost and completion time. It uses a slightly smaller search window for internal simulation to balance accuracy and computational cost.

**Key modifications:**
- Introduction of `_simulate_greedy_future_ops` to simulate the scheduling of remaining operations.
- Modification of `_calculate_placement_score` to accept `_simulated_future_compute_cost` and `_simulated_job_completion_time` instead of `_remaining_ops_duration`.
- The main loop in `schedule_job_online` is updated to call `_simulate_greedy_future_ops` for each candidate placement and pass its results to `_calculate_placement_score`.
- The `EMERGENCY_CLOUD_TRIGGER_DELAY_THRESHOLD` logic is updated to use the more accurate `_simulated_job_completion_time`.
- `remaining_operations_duration` is replaced by `remaining_operations` which is a list of Operation objects.
