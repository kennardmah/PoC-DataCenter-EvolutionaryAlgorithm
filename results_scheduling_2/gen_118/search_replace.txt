<DESCRIPTION>
This edit implements dynamic cloud cost adjustment based on real-time local server congestion (Recommendation 2).
When an operation is considered for a cloud machine, the cloud deterrence factor is dynamically adjusted:
- If local machines compatible with the operation type are heavily congested (below a `LOCAL_CONGESTION_THRESHOLD_RATIO` of their nominal capacity), the cloud deterrence is reduced (`CLOUD_DETERRENCE_MODIFIER_CONGESTED`), making cloud resources relatively cheaper and more attractive. This encourages shifting load to the cloud when local resources are constrained, which is crucial during emergencies or high load periods.
- If local machines are largely abundant (above a `LOCAL_ABUNDANCE_THRESHOLD_RATIO` of their nominal capacity), the cloud deterrence is increased (`CLOUD_DETERRENCE_MODIFIER_ABUNDANT`), making local resources more attractive. This conserves cloud costs when local capacity can comfortably handle the load.
This heuristic aims to balance local vs. cloud cost tradeoffs more intelligently, improving capacity contention and failure resilience by making cloud a more responsive overflow mechanism.
The congestion is calculated based on the *currently available* capacity (considering failures) minus *already scheduled* capacity usage for the specific operation type at the proposed start time.
</DESCRIPTION>
