<name>greedy_lookahead_simulation_v2</name>
<description>
This edit refines the lookahead simulation used when evaluating potential operation placements. Previously, the `remaining_ops_duration` was a simple sum, which did not account for actual machine availability or the cost of different machine types for subsequent operations.

This change introduces a more sophisticated "greedy lookahead" simulation within the `OperationPlacementEvaluator` class:
1.  **`LOCAL_SIMULATION_SEARCH_WINDOW_HOURS`**: A new constant is added to control the search horizon for local machines during the *simulation* of future operations. This keeps the simulation fast while still considering local options.
2.  **`_simulate_remaining_operations_greedy` Method**: A new private method is added within `OperationPlacementEvaluator`. This method performs a greedy simulation of scheduling all *subsequent operations* for the current job.
    *   It takes a `simulated_current_time` (the end time of the current operation being evaluated) and a deep copy of the `capacity_usage`.
    *   For each subsequent operation, it iterates through compatible servers to find the earliest available slot. For local machines, it searches within `LOCAL_SIMULATION_SEARCH_WINDOW_HOURS`. For cloud, it takes the immediate start. It prioritizes the option with the lowest *raw compute cost* for that operation.
    *   It accumulates the total *raw compute cost* of these simulated future operations and tracks the final *simulated completion time* for the entire job.
3.  **Modified `_has_capacity`**: The `_has_capacity` method now accepts an optional `sim_capacity_usage` parameter. This allows it to check capacity against a *simulated* state (for lookahead) or the actual `capacity_usage` (for real placement).
4.  **Enhanced `_calculate_placement_score`**: The `_calculate_placement_score` method is updated to:
    *   Accept `remaining_operations_list` (a list of `Operation` objects) instead of just `remaining_ops_duration`.
    *   Call `_simulate_remaining_operations_greedy` to get more accurate projections of future compute costs and the overall job completion time.
    *   Integrate these simulated future costs and the final completion time into its objective function calculation. This means the current operation's placement decision now considers a more realistic holistic impact on the entire job's cost and deadline penalties.
5.  **Main Loop Update**: The `schedule_job_online` loop is updated to pass the actual list of remaining operations (`job.operations[idx + 1:]`) to the `_calculate_placement_score` method and also to the emergency cloud decision threshold logic.

This improvement allows the scheduler to make more informed local decisions by providing a clearer estimate of the total job cost and completion time, leading to better resource utilization and potentially lower overall costs, especially under dynamic capacity conditions.
</description>

            """Get available capacity at a specific time (for scheduling decisions)."""
            base_capacity = self.inst.servers[server_id].capacity
            if not self.inst.machine_failures:
                return base_capacity

            total_reduction = 0
            for failure in self.inst.machine_failures:
                if failure.machine_id != server_id:
                    continue
                if time < failure.failure_start:
                    continue
                elif time >= failure.failure_end:
                    time_since_end = time - failure.failure_end
                    recovery_factor = 1.0 - math.exp(-failure.recovery_rate * time_since_end)
                    reduction = failure.capacity_reduction * (1.0 - recovery_factor)
                    total_reduction += reduction
                else:
                    time_since_start = time - failure.failure_start
                    failure_factor = 1.0 - math.exp(-failure.failure_rate * time_since_start)
                    reduction = failure.capacity_reduction * failure_factor
                    total_reduction += reduction

            return max(0, base_capacity - int(total_reduction))

        def _has_capacity(self, server_id: str, start: int, duration: int, req: int) -> bool:
            """Checks if a server has enough capacity for an operation over a given time range."""
            for t in range(start, start + duration):
                used = self.capacity_usage[server_id].get(t, 0)
                if used + req > self._get_available_capacity(server_id, t):
                    return False
            return True

            delay = max(0, projected_job_completion - job_ref.deadline)

            total_score = (

            total_score += proposed_start * 0.0001 # Small coefficient for tie-breaking

            return total_score
